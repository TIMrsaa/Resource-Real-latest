# 학습 가이드 — 격리 기술의 종합 시험장

## 이 모듈의 정체

새 기술이 거의 없습니다 — 대신 배운 부품들이 **하나의 설계 문제** 앞에서 조립됩니다:

```
"개발 3팀이 한 클러스터를 쓰되, 서로를 보지도/방해하지도/뚫지도 못하게 하라"

보지도   → RBAC ns 한정 (11)
방해하지도 → ResourceQuota/LimitRange (09) + PriorityClass (12) + 노드 분리 (12)
뚫지도   → NetworkPolicy (15) + PSA (32) — 커널 공유의 한계는 vCluster/클러스터 분리
```

부품이 하나라도 빠지면 어디가 뚫리는지 말할 수 있는가 — 그것이 이 모듈의 합격선입니다.

## 스펙트럼 먼저, 도구는 나중

멀티테넌시 논의가 산으로 가는 이유는 "어느 수준의 격리가 필요한가"를 안 정하고 도구부터 고르기 때문입니다. 질문 순서:

1. 테넌트가 서로 **악의적**일 수 있나요? (외부 고객?) → 커널 공유 자체가 위험 → 강한 격리
2. **노이지 네이버** 허용 한도는? → Quota/노드 분리 수준 결정
3. 테넌트가 **CRD/웹훅 등 클러스터 리소스**를 만져야 하나요? → ns로는 불가 → vCluster
4. 운영 인력은? → 클러스터 N개의 운영 비용이 진짜 문제

이 4문답의 결과가 스펙트럼 위의 위치를 정합니다 — theory에서 표로.
