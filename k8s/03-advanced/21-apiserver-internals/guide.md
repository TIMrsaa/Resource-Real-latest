# 학습 가이드 — 고급 트랙을 읽는 법

## 고급 트랙의 목표 전환

초급/중급은 "쓸 수 있다"가 목표였습니다. 고급은 **"만든 사람의 설계 의도를 읽는다"** 가 목표입니다. 그래서 각 모듈에:

- theory가 더 길고, "소스코드에서 확인하기"가 본문으로 승격됩니다
- lab은 "기능 사용"이 아니라 **"내부 동작의 관측"** 입니다
- 모든 모듈이 기여자 트랙(41~45)의 사전 답사를 겸합니다

## 이 모듈이 첫 번째인 이유

K8s의 모든 것이 API 서버를 지납니다(모듈 02의 철칙). 그러므로:

- 웹훅(모듈 23)은 이 파이프라인의 admission 단계에 끼어드는 것
- CRD(24)는 이 파이프라인에 새 리소스 종류를 등록하는 것
- client-go informer(31)는 이 파이프라인의 watch를 소비하는 것
- RBAC 거부, conflict 에러, Too Many Requests — 전부 이 파이프라인의 특정 단계가 낸 소리입니다

**파이프라인 그림을 암기 수준으로.** 이후 6개 모듈에서 계속 좌표로 씁니다.

## EKS 학습자의 제약과 우회

control plane이 AWS 관리라 API 서버 플래그/로그를 직접 못 만집니다. 대신:
- 클라이언트 쪽 관측: `-v=8`(요청), `kubectl get --watch -v=8`(watch 프로토콜)
- EKS가 노출해주는 것: **감사 로그**(CloudWatch), API 서버 메트릭 일부
- 완전한 자유는 기여자 트랙(모듈 41)의 로컬 kind 클러스터에서 — 거기서 API 서버를 직접 빌드해 돌립니다
