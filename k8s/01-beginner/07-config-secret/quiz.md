## 정답

**A1.** 보안: 비밀값이 이미지 레이어에 박제되어 `docker history`/레지스트리 접근만으로 유출됨. 운영: 환경 수만큼 이미지를 빌드해야 하고 "빌드 한 번, 어디서나 배포" 원칙이 깨짐.

**A2.** 환경변수: **아무 변화 없음** (재시작해야 새 값). 볼륨: kubelet 주기에 따라 수십 초 내 **파일이 원자적으로 교체**됨 (앱이 다시 읽는 것은 별개).

**A3.** `subPath` 마운트.

**A4.** "base64는 **인코딩**(표기법)이지 암호화가 아닙니다 — `| base64 -d`로 1초면 평문입니다. 보호는 RBAC와 etcd 암호화에서 옵니다."

**A5.** ① RBAC로 읽기 권한 통제 ② etcd 저장 시 KMS 암호화(EKS 기본) ③ 노드에서 tmpfs(램) 마운트 ④ 필요한 노드에만 배포 ⑤ 외부 시크릿 매니저 사용(값 자체를 클러스터 밖에).

**A6.** 노드의 IAM 역할에 ECR pull 권한이 있어 kubelet/containerd가 자동으로 인증 토큰을 얻기 때문.

**A7.** Pod가 참조한 ConfigMap/Secret이 **존재하지 않거나 key 오타** — 컨테이너 생성 단계에서 막힙니다.

**A8.** 장점: 실수 변경 방지 + kubelet watch 부하 제거(대규모 성능). 패턴: 이름에 내용 해시를 포함(`cfg-7f3a`)해 **새 이름으로 생성** → Deployment 참조 변경 → 자동 롤링 업데이트.
