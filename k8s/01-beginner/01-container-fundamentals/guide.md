# 학습 가이드 — 왜 컨테이너부터인가

## 이 모듈의 위치

K8s 학습자의 80%가 "Pod, Service, Deployment..." 용어 암기부터 시작했다가, 문제가 생기면 디버깅을 못 해서 좌절합니다. 이유는 단순합니다 — **컨테이너가 뭔지 모르는 채로 컨테이너 오케스트레이터를 배웠기 때문**입니다.

```
[이 모듈]            [다음 모듈들]
컨테이너 = 프로세스  →  Pod = 컨테이너 묶음  →  K8s = Pod 관리 시스템
   (사실)                  (자연스러운 확장)        (자연스러운 확장)
```

## 학습 전략

1. **theory.md를 "믿지 말고" 읽어라.** "컨테이너는 VM이 아니라 프로세스다"라는 주장이 의심스러워야 정상입니다. 그 의심을 lab-01에서 `ps` 명령으로 직접 해소하는 것이 이 모듈의 설계입니다.
2. **명령 결과를 예상하고 실행하세요.** 각 lab의 명령마다 "예상 출력"이 있습니다. 실행 전에 먼저 머릿속으로 예상해보고, 다르면 왜 다른지 따져라.
3. **이미지 = 파일 묶음, 컨테이너 = 실행 중인 프로세스.** 이 구분이 끝까지 헷갈리는 사람이 많습니다. lab-02에서 레이어를 직접 까보며 체득합니다.

## 이 모듈이 끝나면 할 수 있어야 하는 말

- "컨테이너는 가상머신이 아니라, namespace로 시야를 가리고 cgroup으로 자원을 제한한 **리눅스 프로세스**입니다."
- "이미지는 읽기 전용 레이어들의 겹침이고, 컨테이너는 그 위에 쓰기 가능한 레이어 하나를 얹은 것입니다."
- "OCI 표준 덕분에 Docker로 만든 이미지가 containerd에서도 도는 것입니다."
