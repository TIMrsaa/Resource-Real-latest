# 학습 가이드 — 아키텍처를 외우지 말고 "한 문장"에서 유도하세요

## 핵심 한 문장

> **"모두가 API 서버만 바라보고, 각자 자기 일을 조정 루프로 반복합니다."**

K8s 아키텍처 그림에는 컴포넌트가 7~8개 나와서 복잡해 보이지만, 전부 위 문장의 등장인물일 뿐입니다:

- **API 서버**: 모두가 바라보는 유일한 창구
- **etcd**: API 서버가 상태를 적어두는 금고
- **스케줄러**: "노드 미배정 Pod 있나요?"를 반복하는 조정 루프
- **컨트롤러 매니저**: "선언과 현실이 다른가?"를 반복하는 조정 루프 모음
- **kubelet**: "내 노드에 떠야 할 Pod가 떠 있나요?"를 반복하는 조정 루프
- **kube-proxy**: "Service 규칙이 노드에 반영돼 있나요?"를 반복하는 조정 루프

**전부 같은 패턴입니다.** 새 컴포넌트를 만나면 "이 녀석은 무엇을 감시하고(watch), 무엇을 맞추는가(reconcile)?"만 물으면 됩니다.

## 학습 전략

1. theory.md의 전체 그림을 **손으로 따라 그려라**. 그릴 수 있으면 이해한 것이고, 못 그리면 다시 읽어라.
2. lab-01에서 EKS를 만들면 control plane이 **안 보입니다** (AWS가 관리). 이것이 EKS의 본질 — "그림의 왼쪽 절반을 AWS에 외주"임을 체감하세요.
3. lab-02의 이벤트 추적은 이 커리큘럼 전체에서 가장 중요한 실습입니다. 이후 모든 디버깅이 이 체인 위에서 이루어집니다.
