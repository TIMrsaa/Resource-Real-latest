# 학습 가이드 — 코드는 "읽는" 게 아니라 "추적하는" 것입니다

## 소설처럼 읽으면 집니다

수만 파일을 위에서부터 읽는 건 불가능하고 무의미합니다. 숙련자는 **질문을 들고 추적**합니다:

```
나쁜 접근: pkg/ 폴더를 엽니다 → 아무 파일이나 읽습니다 → 3일 후 포기
좋은 접근: "kubectl get은 어떻게 테이블을 만들지?"라는 질문
          → 출력 문구로 grep → 함수 발견 → 호출자/피호출자로 확장
          → 질문에 답할 만큼만 읽고 멈춤
```

이 모듈의 lab이 "원정(expedition)"인 이유 — 목적지(질문)가 있는 이동입니다.

## 도구 준비

- 에디터: VS Code + Go 확장 (정의로 이동 F12, 참조 찾기 Shift+F12 — 이 둘이 90%)
- 터미널: `grep -rn`, `git log -S"문구"` (이 코드가 언제 왜 생겼나)
- 웹: GitHub 검색(리포 한정), https://cs.k8s.io (Kubernetes 코드 검색 엔진)

## 읽기 전술 3종 (theory에서 상세)

1. **문자열 입구**: 에러/로그 문구로 grep — 가장 빠른 입구
2. **인터페이스 추적**: Go의 인터페이스 정의 → 구현체들 → 호출 지점
3. **테스트로 이해**: `*_test.go`가 "이 함수를 어떻게 쓰라는 건지"의 공식 예제집
