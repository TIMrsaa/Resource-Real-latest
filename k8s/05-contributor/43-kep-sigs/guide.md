# 학습 가이드 — 오픈소스의 절반은 "사회"다

## 왜 이 모듈이 코드 모듈들 사이에 있나

기술적으로 완벽한 PR이 묵살되고, 어설픈 PR이 따뜻한 리뷰를 받으며 머지되는 일이 흔합니다. 차이는 **절차와 맥락**:

- 주인 SIG를 못 찾아 아무도 안 보는 곳에 PR을 올렸습니다 (→ 42의 OWNERS가 답)
- 이미 KEP에서 "하지 않기로 결정된" 기능을 구현해 왔습니다 (→ 결정의 역사를 안 읽음)
- 리뷰어가 누군지, 어디서 물어봐야 하는지 몰라 3주간 방치됐습니다 (→ 채널을 모름)

K8s는 세계 최대급의 분산 협업 조직입니다 — 조직도(SIG)와 의사결정 문서(KEP)를 읽을 줄 알면, 코드만 아는 사람보다 기여가 훨씬 빠릅니다.

## 큰 그림

```
결정의 사슬:
  아이디어 → SIG 회의/이슈 논의 → KEP 작성·승인 → 구현 PR들(feature gate 뒤에서)
  → Alpha(1.NN) → Beta → GA → (때로) 폐기
                ↑ 모듈 29에서 본 그 단계들의 "서류 원본"이 KEP
```

모듈 29에서 "기능 발굴 루틴"으로 릴리스 노트를 읽었다면, 이 모듈에선 **그 기능들이 태어난 회의실**로 들어갑니다.

## 한국어 사용자를 위한 한마디

커뮤니티의 공용어는 영어지만, 기여에 필요한 영어는 회화가 아니라 **양식**입니다 — 이슈/PR/리뷰 응답의 표현은 패턴이 정해져 있고(45에서 템플릿 제공), 읽기는 번역기로 충분합니다. 언어를 이유로 미루지 말 것. (참고로 dev 메일링리스트와 Slack엔 비원어민이 절반 이상입니다.)
