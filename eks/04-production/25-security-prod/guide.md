# 학습 가이드 — 하나의 벽이 아니라 여러 겹

## 부품에서 방어선으로

k8s 파트에서 보안 부품을 하나씩 익혔습니다 — RBAC은 누가 뭘 할 수 있나, PSA는 Pod가 얼마나 위험할 수 있나, NetworkPolicy는 누가 누구와 통신하나, admission은 무엇을 허용하나. 각각은 특정 공격 벡터 하나를 막는 벽입니다. 이 모듈의 관점은 다릅니다: **어떤 단일 벽도 뚫린다고 가정하고**, 벽을 여러 겹으로 세웁니다(defense in depth). 공격자가 이미지 스캔을 통과해도 PSA에 막히고, PSA를 우회해도 NetworkPolicy에 막히고, 그것도 뚫려도 IMDS 차단에 막히도록.

## EKS가 더하는 층

k8s의 부품에 AWS가 두 가지를 더합니다:

1. **관리형 위협 탐지**: GuardDuty EKS Protection — 감사 로그(21)에서 이상 API 패턴을, 런타임 모니터링으로 노드 안 악성 행위를 탐지. "방어(막기)"가 아니라 "탐지(알기)"의 층 — 침해는 결국 일어나므로 **얼마나 빨리 아느냐**가 피해를 정합니다
2. **클러스터 밖 시크릿**: Secrets Manager/Parameter Store CSI — k8s Secret의 근본 약점(기본적으로 etcd에 base64로 저장, RBAC 있으면 누구나 열람)을 외부화로 우회 + 자동 회전

## 침해를 가정하세요 (assume breach)

이 모듈의 사고방식은 "뚫리지 않기"가 아니라 "뚫려도 번지지 않기 + 빨리 알기"다:

```
번지지 않기: 최소 권한(9의 IRSA 범위), IMDS 차단(노드 역할 탈취 방지),
            NetworkPolicy(측면 이동 차단 — 18), PSA(권한 상승 차단 — 32)
빨리 알기:   GuardDuty + 감사 로그 + 런타임 탐지 → 자동 대응(격리)
```

## 실습의 경계

GuardDuty는 계정 전역 유료라 활성화는 관리자 협의 영역 — 이 모듈은 그 **탐지 범위와 대응 설계**를 이해하고, 실제 실습은 무료로 가능한 것(Secrets CSI, admission·NetworkPolicy·IMDS 차단)에 집중합니다. 25는 "도구 나열"이 아니라 **관문의 지도와 그 사이를 잇는 논리**를 남기는 게 목표입니다.
