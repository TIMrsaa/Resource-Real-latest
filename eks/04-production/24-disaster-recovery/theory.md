# 이론 — 재건 스택, 격리 사다리, pilot light의 경제학

> **🌱 17세 눈높이 비유: 도시를 다시 짓는 훈련**
> 소방 훈련(장애 대응 — k8s 38)과 다릅니다 — 이건 "도시가 사라졌다"에서 시작하는 훈련:
> - **설계도(IaC)** = 도시의 도면이 다른 도시 금고에 — 도면이 있으면 재건이 시공이고, 없으면 발굴입니다
> - **표준 자재(플랫폼 base)** = 상하수도·전기 규격이 문서로 — 매번 새로 발명하지 않습니다
> - **입주민 명부(GitOps)** = 누가 어디 사는지 git이 압니다 — 명부 포인팅 한 번에 입주 재개
> - **금고 사본(데이터)** = 은행 원장은 **다른 도시 지점**에 실시간 사본 — 이것만은 도면으로 못 만듭니다
> - **pilot light** = 옆 도시에 최소한의 불씨(작은 시청+빈 도로)만 켜두기 — 재해 때 그 불씨에 바람을 붑니다

## 1. RTO의 분해 — 층별 지배 시간

```
RTO_총 = T(선언·판단) + T(1층 인프라) + T(2층 플랫폼) + T(3층 워크로드) + T(4층 데이터) + T(트래픽 전환·검증)
```

| 층 | 내용 | 지배 시간 | 줄이는 법 |
|----|------|----------|----------|
| 판단 | "재해 선언" 결정 | 사람 (의외의 최대 항!) | 선언 기준·권한을 runbook에 명문화 |
| 1층 | CP+노드 (eksctl/IaC — 02) | CP ~20분 + 노드 | **pilot light**: 미리 세워두면 0 |
| 2층 | 애드온·컨트롤러·정책 (11) | 분 단위 (선언돼 있다면) | fleet base(23) — 신규 클러스터 온보딩과 동일 절차 |
| 3층 | 워크로드 | GitOps 재포인팅 (39) | ApplicationSet에 새 클러스터 등록뿐 |
| 4층 | 데이터 | **최대 항** — 복원(크기 비례) 또는 복제 승격(분) | 티어별: 백업 복원 ↔ 상시 복제(36 §4) |
| 전환 | DNS/GA + 검증 | 23의 그 변수들(TTL) | 헬스 깊이·TTL 설계 |

두 개의 정직한 결론: ① 1~3층은 **평소의 선언화**가 이미 결정해뒀다 ② 4층은 돈으로 시간을 사는 층입니다(복제 비용 ↔ 복원 시간).

## 2. 격리 사다리 — 위협별 생존 매트릭스

| 백업 위치 | 리전 장애 | 계정 탈취/ransomware | 관리자 키 탈취 |
|-----------|----------|---------------------|---------------|
| 같은 리전 S3 | ✘ | ✘ | ✘ |
| 크로스 리전 (CRR/다중 BSL) | ✔ | ✘ (같은 계정) | ✘ |
| **타계정** 복제 | ✔ | ✔ | △ |
| + 오브젝트 잠금(WORM) | ✔ | ✔ | ✔ (기간 내 삭제 불능) |

Velero의 구현 손잡이: **BackupStorageLocation 다중화**(리전별 버킷 — lab-01), S3 쪽 구현(CRR·타계정 복제 정책·Object Lock)은 버킷의 일 — 책임 분계가 깔끔합니다.

## 3. 데이터 계층의 두 노선 (36 §4의 리전판)

```
노선 A — 백업/복원: Velero(+EBS 스냅샷 크로스 리전 복사)
   RPO = 백업 주기, RTO = 복원 시간(크기 비례) — 쌉니다
노선 B — 상시 복제: Aurora Global/DynamoDB GT/S3 CRR
   RPO ≈ 초~분(복제 지연), RTO ≈ 승격 시간(분) — 비쌉니다
```

티어링(36)이 여기서도: 결제 DB는 노선 B, 분석 데이터는 노선 A — **서비스마다 노선이 다른 게 정상**입니다. 그리고 23의 경고 재청: failover 순간의 "복제 미도달분" 처리 방침이 없으면 노선 B도 미완성.

## 4. pilot light on EKS — 불씨의 크기 정하기

```
불씨 최소형: CP만 상시 (시간당 고정비) + 노드 0 + fleet 등록 완료
  재해 시: Karpenter(17)가 수요대로 노드 생성 + GitOps 파도 + 데이터 승격
불씨 중형(웜): 최소 노드 + 핵심 서비스 저배율 상시 — 합성 트래픽으로 상시 검증
```

Karpenter가 이 패턴의 경제성을 바꿨습니다 — "대기 클러스터"의 유휴 노드 비용이 거의 0으로. 남는 상시비는 CP 요금과 데이터 복제뿐이며, 그 대가로 1층(최대 20분+)이 RTO에서 사라집니다. 23 사고 사례의 교훈도 여기 접합: **불씨 클러스터도 fleet의 일급 구성원** — 파도에서 빼는 순간 drift가 8개월 쌓입니다.

## 5. Game Day의 승격 — 재건 리허설

36의 Game Day(복구 훈련)를 두 단계 승격: ① 대상이 ns가 아니라 **스택 전체** ② 기록이 "성공 여부"가 아니라 **층별 시간 분해표**. 분해표가 있어야 다음 분기의 투자(어느 층을 줄일까)가 근거를 가집니다 — lab-02가 그 첫 회입니다.
