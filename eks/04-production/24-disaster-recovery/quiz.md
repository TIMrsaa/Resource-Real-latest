**Q1.** 재건 스택 4층과 각 층의 "원본"(무엇에서 재건하나)을 매핑하세요.

**Q2.** "무상태 워크로드는 백업하지 않는다"가 성립하는 조건과 그 함의는?

**Q3.** RTO 분해에서 흔히 최대 항이 되는 두 단계(기술 1, 비기술 1)와 각각의 처방은?

**Q4.** 격리 사다리 4칸과 각 칸이 추가로 막아주는 위협은?

**Q5.** Velero 다중 BSL과 S3 쪽 기능(CRR·Object Lock)의 책임 분계는? 이 분리의 가치는?

**Q6.** pilot light on EKS의 상시 비용 구성과, Karpenter(17)가 바꾼 것은?

**Q7.** 4층(데이터)의 두 노선과 티어링 — 결제 DB와 분석 데이터가 다른 노선을 타는 이유는?

**Q8.** Game Day의 산출물이 "성공/실패"가 아니라 "분해표"여야 하는 이유는?

## 정답

**A1.** 1층 인프라 ← IaC 선언(eksctl config — 02). 2층 플랫폼 ← fleet base(애드온·컨트롤러·정책 — 11·23). 3층 워크로드 ← git(GitOps — 39). 4층 데이터 ← **백업/복제**(Velero·DB — 유일하게 선언으로 못 만드는 층).

**A2.** 조건: 선언(git)이 완전한 원본일 것 — 이미지·매니페스트·설정이 전부 코드로. 함의: 백업 대상이 극적으로 줄어(Secret·PV·DB만), 3층 재건이 "복원"이 아니라 "재배포"가 됩니다 — GitOps 위생이 곧 DR 자산이라는 것.

**A3.** 기술: 4층 데이터 복원(크기 비례) — 처방: 핵심 티어만 상시 복제(노선 B)로 승격해 복원을 승격으로 대체. 비기술: **재해 선언 판단**(회의로 증발하는 첫 1시간) — 처방: 선언 기준·권한자·면책을 runbook에 명문화.

**A4.** ① 같은 리전: (기준선). ② 크로스 리전: 리전 장애 생존. ③ 타계정: 계정 탈취·ransomware의 백업 동반 삭제 차단. ④ Object Lock(WORM): 관리자 권한 탈취에도 기간 내 삭제 불능. 위협 모델의 높이만큼 오릅니다.

**A5.** Velero: "어느 금고(BSL)에 넣나"까지 — 백업의 행선지 정책. S3: 금고 자체의 요새화 — 복제(CRR·타계정)와 불변(Object Lock). 가치: 백업 도구를 교체해도 격리 설계가 살아남고, 각 층을 각자의 전문가(플랫폼팀/보안팀)가 소유할 수 있습니다.

**A6.** 상시비 = CP 시간 요금 + 데이터 복제 비용 (+최소한의 웜 노드 선택). Karpenter가 바꾼 것: 대기 클러스터의 **유휴 노드 비용을 ~0으로** — 재해 시 수요 기반으로 노드를 만들면 되므로, "빈 클러스터를 세워두는" 것의 경제성이 성립하게 됐습니다(1층 20분의 소거를 CP 요금만으로 삽니다).

**A7.** 노선 A(백업/복원): RPO=주기, RTO=크기 비례 — 쌉니다. 노선 B(상시 복제): RPO≈초, RTO≈승격 시간 — 비쌉니다. 결제 DB는 유실·중단의 비용이 복제 비용을 압도(→B), 분석 데이터는 재집계 가능하고 커서 복제가 낭비(→A) — 36의 티어링 논리가 노선 선택으로 이어집니다.

**A8.** 총점("4시간 걸림")은 다음 행동을 못 정합니다 — 층별 시간이 있어야 병목이 보이고, 개선 투자(pilot light? 복제 승격? 문서화?)가 근거를 가집니다. 분해표는 DR 예산의 유일한 실증 자료이자, 다음 Game Day와의 비교 기준선입니다.
