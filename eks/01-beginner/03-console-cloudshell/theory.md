# 이론 — 콘솔의 구조와 동작 원리

> **🌱 17세 눈높이 비유: 학교 행정실 창구 vs 교무 수첩 vs 방송실**
> 같은 학교를 다루는 세 도구: **행정실 창구(콘솔)** 는 전체 현황판과 민원 — 한눈에 보기 좋지만 같은 서류를 매번 손으로. **교무 수첩(CLI/kubectl)** 은 익숙해지면 가장 빠르고, 적어두면(스크립트) 누구나 재현 가능. **방송실(CloudShell)** 은 내 수첩이 없어도 학교 안 어디서든 쓸 수 있는 비치 장비입니다.
> 그리고 중요한 사실: 행정실 직원(콘솔)도 **결국 같은 명단(access entry)을 확인하고** 움직입니다 — 콘솔이라고 특별 통로가 아닙니다.

## 1. EKS 콘솔의 6개 영역 — 무엇이 어디에

```
클러스터 상세 화면:
├ 개요         버전/상태/endpoint — describe-cluster의 GUI판 (모듈 01 lab-01)
├ 리소스       Pod/Deployment/Node... K8s 객체 열람 ★ 원리는 §2
├ 컴퓨팅       노드그룹/Fargate 프로파일/Karpenter — 스케일 설정 (eks 05,17)
├ 네트워킹     VPC/서브넷/엔드포인트 접근 (eks 07,16)
├ 추가 기능    관리형 애드온 상태/버전 (eks 11)
├ 액세스       access entries의 GUI (모듈 02에서 만진 그것)
└ 관측성       insights(업그레이드 차단 요소!), 메트릭/로그 연결 (eks 12, k8s 35)
```

운영자가 가장 자주 여는 두 곳: **관측성의 insights**(업그레이드 전 점검 — k8s 35)와 **컴퓨팅의 노드 헬스**.

## 2. 리소스 뷰의 원리 — 콘솔도 한 명의 클라이언트

콘솔이 Pod 목록을 보여주는 경로:

```
브라우저의 나 → (AWS 로그인된 IAM 주체로) → 콘솔 백엔드가 그 IAM으로
  EKS API 서버에 K8s API 호출 → access entry 매핑 → RBAC/policy 평가 → 결과 표시
```

즉 **콘솔은 "내 IAM으로 kubectl을 대신 쳐주는" 웹 클라이언트**입니다. 따라서:

- 콘솔 로그인 IAM에 access entry가 없으면 → 리소스 탭에 권한 오류 (EKS 최다 질문 중 하나의 정체)
- 콘솔에서 보인다/안 보인다 = 그 IAM의 K8s 권한 그대로 (kubectl과 동일 기준)
- 해결은 콘솔 설정이 아니라 **access entry 추가**(모듈 02 lab-02) — View 정책이면 열람 충분

## 3. CloudShell — 브라우저 속 운영 터미널

- 콘솔 우상단 터미널 아이콘 — **현재 로그인한 IAM 자격증명이 자동 주입**된 리눅스 셸
- AWS CLI 최신 내장, 홈 디렉터리 1GB 영속(리전별) — kubectl/eksctl은 설치 필요(매번 또는 ~/bin에)
- 용도: 비상 대응(내 장비 없음), 일회성 확인, 교육/시연
- 한계: 세션 타임아웃, 무거운 작업(빌드) 부적합, 리전별 홈 분리

## 4. "어느 도구로?"의 결정 기준

| 작업 | 도구 | 이유 |
|------|------|------|
| 노드그룹 스케일 변경 | CLI/ClusterConfig | 기록·재현 (콘솔 클릭은 휘발) |
| 장애 중 상태 파악 | 콘솔 (+kubectl) | 한눈 + insights |
| Deployment 수정 | kubectl/GitOps | K8s 안쪽은 매니페스트가 진실 (k8s 39) |
| 신기능 탐색 | 콘솔 | 새 탭/배너로 먼저 노출되는 경우가 많습니다 |
| 반복 점검 | CLI 스크립트 | 모듈 01 lab-02의 전수 조사처럼 |
| 비상(장비 없음) | CloudShell | 자격증명 자동 + 어디서나 |

**감사 관점 보충**: 콘솔 클릭도 CloudTrail에는 남습니다(EKS API 호출로). 하지만 "왜"가 없는 기록입니다 — 변경은 코드+리뷰로 남기는 것이 운영 문화(k8s 39의 GitOps 원칙과 동일선).

## 요약 카드

| 질문 | 답 |
|------|----|
| 콘솔 리소스 뷰의 정체? | 내 IAM으로 K8s API를 대신 호출하는 웹 클라이언트 |
| 콘솔에 Pod가 안 보임? | 그 IAM의 access entry/권한 부재 — 콘솔 설정 아님 |

| 변경 작업의 원칙? | 코드(CLI/IaC/매니페스트)로 — 콘솔 클릭은 휘발 |
| CloudShell의 용도? | 비상/일회성 — 자격증명 자동 주입 터미널 |
