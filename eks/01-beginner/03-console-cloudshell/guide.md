# 학습 가이드 — 도구마다 "잘하는 일"이 다릅니다

## 세 도구의 역할 분담 (이 모듈의 결론 미리)

| 도구 | 잘하는 것 | 못하는/부적합한 것 |
|------|----------|-------------------|
| **콘솔** | 한눈 파악(버전/노드/애드온 상태), 관측 대시보드, 신규 기능 발견, 비상시 GUI | 반복 작업, 자동화, 변경 이력(클릭은 기록 안 남음) |
| **AWS CLI/eksctl** | EKS 객체 조작(노드그룹/애드온/entry), 스크립트화 | K8s 안쪽(Pod/Deployment) 조작 |
| **kubectl** | K8s 객체 전부 (k8s 파트 전체) | AWS 객체(노드그룹 스케일 설정 등) |

원칙: **변경은 코드(CLI/IaC)로, 파악은 콘솔로, K8s 안쪽은 kubectl로.** 콘솔에서 "수정" 버튼이 보여도 누르기 전에 "이거 ClusterConfig/매니페스트로 해야 하는 것 아닌가"를 묻는 습관.

## 왜 콘솔을 굳이 배우나

- 장애 콜에서 가장 빠른 **상황판**입니다: 클러스터 상태/insights/노드 헬스가 한 화면
- 팀의 비개발 직군(매니저/감사)이 보는 화면 — 그들이 묻는 "콘솔에서 빨간 거"의 정체를 알아야 합니다
- 리소스 뷰의 권한 오류가 **access entry 이해도를 시험하는 단골 문제**입니다 (lab-01에서 일부러 겪습니다)

## CloudShell의 자리

"내 노트북이 아닌 곳"(출장, 비상, 새 장비)에서 브라우저만으로 AWS 자격증명이 잡힌 터미널 — kubectl만 깔면 즉시 운영 가능. 비상 runbook(eks 26)의 전제 도구이니 미리 손에 익혀둡니다.
