# 이론 — 경계선, 요금, 지원 정책, 공유 책임

> **🌱 17세 눈높이 비유: 자취 vs 기숙사**
> 자체 운영(kubeadm)은 **자취**입니다 — 보일러(etcd)가 고장 나면 새벽에 내가 고칩니다. 자유롭지만 모든 게 내 일.
> EKS는 **기숙사**입니다 — 건물 관리(control plane)는 사감(AWS)이 하고 월세($0.10/h)를 냅니다. 대신:
> - 내 방 정리(워크로드), 룸메이트 규칙(RBAC/quota), 내 짐(데이터)은 **여전히 내 일**
> - 건물 구조(etcd 설정)는 **못 바꿉니다** — 관리형의 본질은 "편의와 통제의 교환"
> - 그리고 기숙사 규칙(지원 버전 정책)을 어기면 **벌금(연장 지원 과금)** 이 나옵니다

---

## 1. 경계선 — 누가 무엇을 운영하나

```
┌──────────── AWS 영역 (보이지 않는 곳) ─────────────┐
│ API 서버 (멀티 AZ HA, 부하 따라 자동 스케일)        │ k8s 21
│ etcd (운영/백업/암호화 — 접근 불가)                 │ k8s 22
│ 스케줄러/컨트롤러 매니저                            │ k8s 25
│ control plane 패치/가용성 SLA                      │
├──────────── 경계의 회색지대 ───────────────────────┤
│ 관리형 노드그룹: 노드 수명주기는 AWS 도구, EC2는 내 계정│ eks 05
│ 관리형 애드온(VPC CNI/CoreDNS/kube-proxy): 설치는    │ eks 11
│   AWS, 버전 선택/설정은 나                          │
│ EKS Auto Mode: 회색지대 대부분을 AWS 쪽으로         │ eks 04
├──────────── 내 영역 ──────────────────────────────┤
│ 워크로드 전부 (Deployment/Service/...)             │ k8s 전체
│ 노드 안의 문제 (이미지, 리소스, OOM)                │
│ 네트워크 설계 (VPC/서브넷/IP 계획!)                 │ eks 07,16
│ IAM/RBAC 통합, 시크릿                              │ eks 09,25
│ 업그레이드 트리거와 호환성 검증                      │ eks 21
│ 비용                                               │ eks 22
└────────────────────────────────────────────────────┘
```

핵심 함의 두 가지:
- **etcd를 만질 수 없습니다** → 백업은 Velero(리소스 레벨, k8s 36), etcd 튜닝 대신 객체 위생(k8s 37)
- **API 서버 플래그를 못 바꿉니다** → admission 체인 커스텀은 웹훅/정책(k8s 23)으로, 감사 로그는 CloudWatch로(k8s 21 lab-02)

## 2. 요금 구조 — 어디서 돈이 새나

| 항목 | 과금 | 메모 |
|------|------|------|
| 클러스터(control plane) | **$0.10/시간** (~$73/월) | 켜둔 것만으로. 클러스터 수가 곧 고정비 |
| 노드 (EC2) | 인스턴스 요금 그대로 | 최대 비용원. Spot/Graviton이 절감 레버(22) |
| 연장 지원 클러스터 | **$0.60/시간** (6배!) | 구버전 방치의 벌금 (21) |
| NAT Gateway | 시간 + GB당 | 프라이빗 서브넷 노드의 숨은 비용 |
| ELB(ALB/NLB) | 시간 + LCU/NLCU | Ingress 하나 = LB 하나면 폭증 (08) |
| EBS/EFS | 프로비저닝 GB | 잔존 PVC가 주범 (k8s 19 pitfall) |
| 데이터 전송 | AZ 간/아웃바운드 GB | 대규모에서 복병 (14) |

> Fargate는 Pod 단위 과금(vCPU+메모리), Auto Mode는 별도 요금 구조 — 각 모듈에서.

## 3. 버전과 지원 정책 — 시간이 곧 돈

- 분기마다 새 마이너 지원, 각 버전 **표준 지원 14개월** → 이후 **연장 지원 12개월(시간당 6배 과금)** → 그 후 강제 업그레이드 대상
- 함의: **1년에 한두 번의 업그레이드는 선택이 아니라 재정 계획**입니다 (k8s 35의 "작게 자주"가 여기서 돈으로 환산됩니다)
- 버전 확인과 달력 잡기가 운영 루틴 (lab-01에서 실측)

## 4. 공유 책임 모델 (보안 관점)

```
AWS 책임:   control plane 인프라 보안, etcd 암호화, 관리형 노드 OS 패치(AMI 제공)
내 책임:    IAM 정책 최소화, 워크로드 보안(k8s 32/33), 노드 패치 적용(AMI 교체 트리거),
           네트워크 노출(엔드포인트/SG), 데이터 암호화 선택, 감사 로그 활성화
```

"관리형이니 보안도 알아서"가 가장 위험한 착각 — **사고 사례의 대부분은 내 책임 영역**(과한 IAM, 공개 엔드포인트+느슨한 RBAC, 패치 안 된 노드)에서 납니다.

## 5. 선택지 스펙트럼 (언제 무엇을)

| 선택지 | control plane | 노드 | 적합 |
|--------|---------------|------|------|
| kubeadm 자체 운영 | 나 | 나 | 특수 요구(플래그 커스텀), 학습(k8s 41), 온프레미스 |
| EKS + 자체 노드 | AWS | 나 (ASG 직접) | 세밀한 노드 제어 |
| **EKS + 관리형 노드그룹** | AWS | 회색(도구는 AWS) | **표준 선택** — 이 커리큘럼 |
| EKS + Fargate | AWS | AWS (노드 개념 소멸) | 소규모/배치/노드 운영 제로 (06) |
| EKS Auto Mode | AWS | AWS (Karpenter 내장) | 신규 클러스터 기본 후보 (04) |
