# 자가 점검 퀴즈

**Q1.** EKS 경계선의 3구역(AWS/회색/나)을 각각 대표 항목 2개씩으로 그려라.

**Q2.** "etcd 접근 불가"가 백업 전략과 성능 튜닝에 각각 주는 함의는? (k8s 36/37 연결)

**Q3.** EKS 비용의 3대 덩어리와, "kubectl로 안 보이는" 비용원 3가지는?

**Q4.** 표준/연장 지원 정책과 그것이 강제하는 운영 루틴은?

**Q5.** 관리형 노드그룹이 "회색지대"인 이유를 EC2 직접 종료 실험으로 설명하세요.

**Q6.** describe-cluster에서 supportType, platformVersion, endpointPublicAccess 각각이 알려주는 것은?

**Q7.** 휴지기에 노드그룹을 0으로 했습니다 — 그래도 나가는 돈과 사라지는 것은?

**Q8.** "EKS인데 왜 배워야 하나"에 대한 이 모듈의 답을 한 문장으로.

---

## 정답

**A1.** AWS: API 서버 HA, etcd 운영/백업, 스케줄러/컨트롤러, CP 패치. 회색: 관리형 노드그룹(수명주기는 AWS 도구, EC2/요금은 나), 관리형 애드온(설치는 AWS, 버전/설정은 나). 나: 워크로드 전부, VPC/IP 설계, IAM·RBAC 통합, 업그레이드 트리거, 비용.

**A2.** 백업: etcd 스냅샷 불가 → 리소스 레벨 백업(Velero)이 주 도구. 튜닝: etcd 쿼터/컴팩션을 못 만지므로 → **객체 위생**(시체 정리, TTL)과 클라이언트 매너(LIST 패턴)로 내 쪽에서 부하를 줄이는 것이 유일한 레버.

**A3.** 3대: 노드(EC2) + control plane($0.10/h, 연장 시 $0.60/h) + NAT Gateway. 안 보이는 것: LB(Ingress/Service가 생성), 잔존 EBS(PVC 시체), 미사용 EIP/스냅샷, AZ 간 데이터 전송.

**A4.** 마이너 버전마다 표준 14개월 → 연장 12개월(6배 과금) → 강제 업그레이드. 루틴: 전 클러스터의 지원 종료일을 달력화, 연 1~2회 업그레이드를 정기 작업으로(k8s 35 runbook) — 미루기의 가격이 명시적입니다.

**A5.** 노드그룹 소속 EC2를 직접 terminate하면 — EKS(ASG)가 새 EC2를 만들어 되돌립니다. 인스턴스와 요금은 내 계정(나의 것)인데 수명주기 결정권은 AWS 도구에 있습니다 — 소유와 통제가 분리된 회색지대.

**A6.** supportType: STANDARD/EXTENDED — 과금 6배 여부. platformVersion: 같은 K8s 버전 내 AWS의 CP 패치 레벨(AWS가 자동 진행 — 경계선 너머의 변화). endpointPublicAccess: API 서버의 인터넷 노출 여부 — 내 책임의 보안 설정.

**A7.** 나가는 돈: control plane $0.10/h + LB/NAT/EBS/EIP(노드와 수명 독립). 사라지는 것: 모든 Pod(와 emptyDir 데이터) — PVC/외부 저장소의 데이터는 보존, 클러스터 설정/객체도 보존(etcd는 AWS가 유지).

**A8.** 관리형은 운영을 위로 올릴 뿐 없애지 않습니다 — 경계선 너머(CP)의 동작까지 이해하고 경계선 안(IP/IAM/스케일/비용)을 실측으로 운영하는 사람이 EKS를 "잘 쓰는" 사람입니다.
