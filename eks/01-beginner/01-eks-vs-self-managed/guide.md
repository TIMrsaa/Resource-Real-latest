# 학습 가이드 — eks 파트를 읽는 법

## k8s 파트와의 관계

k8s 파트는 "Kubernetes라는 기계"를 다뤘습니다. eks 파트는 **"그 기계를 AWS라는 공장에 설치했을 때"** 생기는 모든 것을 다룹니다:

```
k8s 파트에서 배운 것          eks 파트에서 그것이 만나는 현실
─────────────────────────────────────────────────────
etcd/API 서버 (21,22)    →   AWS가 운영 — 대신 우리는 한도/관측만 (01)
CNI 일반론 (27)          →   VPC CNI의 ENI/IP 경제학 (07,16)
Service/Ingress (05,06)  →   ALB/NLB의 실물과 튜닝 (08,14)
RBAC (11)                →   IAM과의 결혼: IRSA/Pod Identity (09)
HPA (13)                 →   RPS 기반 스케일링 실전 (13~15)
Cluster Autoscaler 개념   →   Karpenter 내부까지 (17)
업그레이드/DR (35,36)     →   EKS runbook으로 실전화 (21,24)
기여 (41~45)             →   Karpenter/VPC CNI에 같은 루프로 (27~29)
```

**같은 원리, 다른 실물** — k8s 파트의 모듈 번호를 계속 역참조하니, 막히면 그 모듈로 돌아가라.

## 이 파트의 고유 주제: 측정

eks 파트의 심장은 고급 트랙(13~15)입니다 — **RPS를 직접 만들고, 측정하고, 그 수치로 스케일링을 설계**합니다. "우리 서비스 몇 RPS까지 버텨요?"에 실측으로 답하는 능력 — 클라우드 운영자의 몸값이 갈리는 지점입니다.

## 비용 경고 (모든 모듈 공통)

EKS는 켜두는 것만으로 돈이 나갑니다: 클러스터 $0.10/h + 노드(EC2) + NAT/LB/EBS. 각 모듈의 cleanup을 반드시 실행하고, **학습 휴지기엔 노드그룹을 0으로** (lab-02에서 절차화). 한 달 방치 = 수십만 원이 현실이 됩니다.

## 첫 질문

"관리형인데 배울 게 있나요?" — 관리형은 **운영을 줄여주지 책임을 없애주지 않습니다**. control plane이 죽을 걱정은 사라지지만, IP 고갈로 Pod가 안 뜨고(16), IRSA 토큰이 만료되고(09), ALB 한도에 걸리는(14) 것은 전부 내 새벽 콜입니다. EKS를 잘 쓴다 = **경계선 너머의 동작까지 이해하고 경계선 안쪽을 완벽히 운영합니다.**
