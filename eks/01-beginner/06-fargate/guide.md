# 학습 가이드 — 세 가지 컴퓨팅의 자리 찾기

## 초급 트랙의 마지막 퍼즐

01~05에서 모은 조각:

```
관리형 노드그룹(05)   노드를 "풀"로 직접 설계·운영       — 통제 최대
Auto Mode(04)        노드는 있되 운영이 사라짐           — 균형점
Fargate(06)          노드 개념 자체가 없음 (Pod=VM)      — 운영 최소, 제약 최대
```

이 모듈을 마치면 "이 워크로드는 어디에?"라는 질문에 **결정표**로 답할 수 있습니다 — 초급 졸업의 기준입니다.

## Fargate를 한 문장으로

**"Pod마다 전용 미니 서버를 그 순간 빌려주는 것."** 함의가 줄줄이 따라옵니다:

- 이웃이 없습니다 → noisy neighbor(k8s 09) 원천 차단, 커널 공유 격리 문제(k8s 32)도 VM 격리로 해소 → **멀티테넌트/민감 워크로드에 강함**
- 노드가 없습니다 → DaemonSet이 설 곳이 없고, 노드 로컬의 모든 것(hostPath, 이미지 캐시)이 없습니다
- Pod 단위 과금 → 띄엄띄엄 도는 소량 워크로드에 유리, 상시 대량엔 EC2보다 비쌈

## 솔직한 위치 평가

Auto Mode 등장 이후 Fargate의 입지는 좁아졌습니다 — "노드 운영 제로"라는 가치를 Auto Mode가 더 적은 제약으로 제공하기 때문. 그래도 남는 자리: **VM 격리가 필요한 보안 요건**, Pod 단위 과금이 맞는 패턴, 기존 Fargate 운영 클러스터. "역사적 선택지 + 특수 요건의 도구"로 정확히 자리매김하고 배우자 — 면접/실무에서 "왜 Fargate 안 썼어요?"에 답하는 것까지가 학습입니다.
