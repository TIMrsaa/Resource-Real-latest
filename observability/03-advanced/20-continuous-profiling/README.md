# 20 — 지속 프로파일링: "왜 그 코드가 느린가"의 마지막 신호

> 관측의 마지막 심도. 트레이스(04·11)가 "어느 서비스·어느 구간"까지, eBPF(19)가 "어느 통신"까지 좁혀 줬다면 — 그 안에서 **어느 함수가 CPU를 태우고, 어느 코드가 메모리를 잡고 있는가**는 프로파일링의 영토입니다. 전통 프로파일링은 "문제 있을 때 붙이는 무거운 도구"였지만, 지속 프로파일링(continuous profiling)은 낮은 오버헤드 샘플링(eBPF 기반이 대세 — 19의 기술이 여기서도)으로 **항상 켜 두고**, "지난 화요일 배포 전후의 CPU 프로파일 비교" 같은 질문에 답합니다. Parca·Pyroscope로 실습하고, 플레임그래프 읽기, 메모리 누수 조사(05 카탈로그의 그 질문), 트레이스와의 연결(span→프로파일), 그리고 "언제 이 층이 필요한가"를 판단합니다.

## 학습 목표

1. 프로파일의 종류(CPU·heap·goroutine 등)와 샘플링 원리(오버헤드가 낮은 이유)를 압니다
2. 플레임그래프를 읽습니다 (넓이=시간, 세로=콜스택 — 병목 함수 짚기)
3. 지속 프로파일링을 배포하고(Parca/Pyroscope) 시간·버전 간 비교(diff)를 수행합니다
4. 메모리 누수 조사 동선(메트릭 추세→heap 프로파일→코드)을 완성합니다 (05·03의 숙제)
5. 관측 4신호+프로파일의 전체 영토 지도를 완성하고 도입 판단을 세웁니다
