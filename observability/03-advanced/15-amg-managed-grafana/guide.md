# 학습 가이드 — 화면은 가볍고, 통합은 무겁습니다

## Grafana 운영의 실체 — 무엇이 부담이었나

cncf 42(Backstage)에서 "Node 앱 운영의 부담"을 봤듯, Grafana도 자체 운영엔 실체가 있습니다:

```
서버·DB(대시보드 저장)·업그레이드·플러그인 호환
인증 통합 (SSO — 기업에선 이게 제일 골치)
데이터소스 자격 증명 관리 (CW 키? AMP SigV4 프록시?)
HA (Grafana가 죽으면 장애 조사 화면이 없습니다 — 09 사고의 도구판)
```

AMG는 이것들을 넘겨받습니다 — 특히 **인증(Identity Center)과 AWS 데이터소스 자격(IAM 롤)**의 통합이 자체 대비 확실한 우위입니다. 반면 대가도 있습니다: 활성 사용자당 과금, 플러그인·버전의 제약, 커스터마이즈 폭.

## 이 모듈의 그림 — 세 신호가 한 화면에

```
AMG 워크스페이스
  ├─ 데이터소스: AMP        (메트릭 — 14의 그것, SigV4 자동)
  ├─ 데이터소스: CloudWatch (로그·플랫폼 메트릭 — 13, IAM 롤)
  ├─ 데이터소스: X-Ray      (트레이스 — 17 예고, IAM 롤)
  └─ 인증: Identity Center  (누가 보나 — 기업 SSO)

→ 12에서 오픈소스로 만든 "한 화면의 상관"이
  AWS 부품(AMP·CW·X-Ray)으로 재현됩니다 — 17을 마치면 완성
```

핵심 관찰: 자격 증명이 전부 **IAM 롤**입니다 — API 키·비밀번호를 어디에도 저장하지 않습니다. 14의 IRSA와 같은 사상(키 없는 인증)이 화면 층에서도.

## as code의 긴장 — 관리형에서도 규율은 우리 몫

09의 규율(Git이 진실, UI는 초안)이 AMG에서 어떻게 되나:

```
자체 Grafana: sidecar가 ConfigMap을 로드 (클러스터 안이라 자연스러움)
AMG: 클러스터 밖 — sidecar 패턴이 없습니다
  대안: Grafana API(서비스 어카운트 토큰)로 대시보드 push
       Terraform grafana provider로 선언 관리
       Git 저장소 → CI가 API 호출 (GitOps의 변형)
→ 도구가 바뀌어도 "대시보드는 Git에, uid 고정"의 규율은 유지해야
  (관리형이 규율까지 대신해 주지 않습니다 — 14의 결론과 동일)
```
