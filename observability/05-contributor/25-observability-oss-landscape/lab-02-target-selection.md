# Lab 02 — 정찰 시트와 대상 선정

> cncf 49의 정찰 시트와 50의 선정 기준(관심×역량×건강)을 결합해, 26에서 실제로 걸을 기여 대상 하나를 결정합니다. 결정의 근거를 문서화하는 것까지가 실습입니다.

## 1. 관심 축 — 파트의 어디가 재밌었나

```
자기 점검 (솔직하게 — 억지는 못 갑니다, cncf 50):
  □ 06~07(파이프라인의 물리)가 재밌었습니다 → fluent 계열
  □ 03·08(메트릭·수집 체계)가 재밌었습니다 → prometheus 계열
  □ 04·11·16(트레이스·계측·Collector)가 재밌었습니다 → open-telemetry
  □ 09·12(화면·상관)가 재밌었습니다 → grafana 플러그인 생태
  □ 19·20(eBPF·프로파일링)이 재밌었습니다 → parca·pyroscope·OTel eBPF
복수라면: 실무와 겹치는 쪽 (운영하며 기여하는 선순환 — cncf 50 사례)
```

## 2. 역량 축 — 언어와 형태

```
주력 언어 → 경로 매핑:
  Go      → fluent-bit 플러그인·exporter·Collector contrib·본체들 (최다 경로)
  Python/Java/JS → OTel 해당 언어 SIG (계측·SDK)
  C       → fluent-bit 코어 (파서·버퍼 — 06의 theory가 코드로)
  Ruby    → fluentd·플러그인
  TypeScript → Grafana 패널/데이터소스 플러그인
  "코드는 아직" → 문서·재현·트리아지 (전 생태계 공통 — 50의 정석 시작)
```

## 3. 건강 축 — lab-01 온도표 + 49 시트

lab-01의 온도표에 49의 정찰 시트(의사결정·기여 절차·사다리·초보 진입로)를 겹쳐, 후보 2~3개를 표로 비교합니다.

## 4. 결정 — 선정 문서 작성 (cncf 48의 ADR 형식으로)

```markdown
# 기여 대상 결정 — <이름>

## 결정
<프로젝트/저장소> (예: opentelemetry-python의 instrumentation,
 또는 fluent-bit의 out_<우리시스템> 플러그인, 또는 node_exporter의 X collector)

## 근거 (3축)
관심: 파트에서 11(계측)이 가장 재밌었고 실무에서 Python 서비스 계측 중
역량: Python 주력, 11에서 자동 계측의 주입 메커니즘을 이해함
건강: (lab-01 근거) — SIG 회의 활발, good-first-issue 신선,
     CONTRIBUTING 명확, 외부 PR 처리 O일 수준

## 첫 행보 (cncf 50 lab-01의 체크리스트 대입)
잠복: SIG 슬랙 채널·최근 회의록 2개·머지된 PR 5개 읽기
첫 기여 후보: (탐방에서 본) 이슈 #NNNN 재현 / 문서의 X 절 개선 /
            미지원 라이브러리 Y의 계측 (작게 시작!)

## 재평가 조건
3개월간 응답 부재·방향 불일치면 → 2순위(<대안>)로
```

**작성 규칙** — 각 근거는 lab-01에서 "직접 본 것"으로. 첫 기여 후보는 **이 파트의 경험에서 나온 것**이 최선입니다(예: 11 실습에서 실제로 미지원이던 라이브러리, 06에서 실제로 헤맨 문서 — 진짜 마찰이 진짜 기여입니다).

## 5. 파트 경험 → 첫 기여 재료의 예시 매핑

```
실습에서 겪었을 법한 마찰 → 기여 형태:
  "kind에서 이 helm 값이 문서와 달랐다" → 문서 PR (chart repo)
  "P/F 재조립 문서에 이 케이스가 없다"(06) → fluent-bit docs
  "예제 앱 메트릭에 service 라벨이 없어 헤맸다"(09) → 예제·문서 개선
  "우리 사내 시스템 exporter가 없다"(03·08) → 신규 exporter (자기 영토!)
  "tail_sampling 정책 문서의 예시 부족"(11) → contrib README
  "Instrumentation CRD의 이 언어 예시가 없다"(11) → operator docs
→ SIGNALS-MAP·실습 노트를 뒤져 "내가 막혔던 곳" 목록을 만들라 —
  그것이 가장 정직한 기여 백로그입니다
```

## 6. SIGNALS-MAP 최종 갱신

```
기여 열 추가:
  대상: (결정 문서 링크)
  첫 행보: 잠복 계획·첫 기여 후보
갱신 로그: "25 수료 — 기여 대상 확정. 26에서 빌드와 첫 기여로"
```

## 정리

- 3축 교집합(관심×역량×건강)으로 하나를 — 근거는 전부 직접 본 것
- 결정을 ADR 형식으로 문서화 (재평가 조건까지 — 48의 규율)
- 첫 기여 후보는 파트의 실제 마찰에서 — 진짜 마찰이 진짜 기여
- "코드는 아직"이어도 경로는 있습니다 — 문서·재현·트리아지(50의 정석)
