# Lab-02 — HA·테넌시 설계와 규모별 판단 지도

> HA 수집과 dedup의 원리를 확인하고, 테넌시(격리·쿼터·귀속)를 설계 연습한 뒤, 이 파트의 최종 산출물인 규모별 판단 지도를 완성합니다. production 트랙의 마무리입니다.

## 0. 준비 (lab-01 이어서)

## 1. HA 수집과 dedup (원리 확인)

```
구성 스케치 (실습 리소스 절약을 위해 설계 확인 중심):
  prometheusSpec:
    replicas: 2                          # 같은 대상을 2벌 수집
    replicaExternalLabelName: replica    # 자동으로 replica: prometheus-X 라벨

  Thanos Query 인자:
    --query.replica-label=replica        # ★ 이 라벨은 "같은 데이터의 복제"로 취급

효과 확인 (질의 관점):
  dedup 없이: up{cluster="east"}가 replica별 2줄
  dedup 켜면: 1줄로 병합 — 한쪽의 수집 공백은 다른 쪽 데이터로 메워짐
  → "서로 다른 구멍이 난 두 벌을 잇는다" (평균이 아니라 선택·병합)

비용 판단: 수집·저장 2배 — 전부가 아니라 핵심(SLO·алert 재료)에 값어치
  (22의 등급 사상: HA도 등급별로)
```

## 2. 테넌시 설계 연습 — 공유 저장소의 규칙 만들기

시나리오: 팀 40개가 중앙 메트릭 저장소(Mimir류)를 공유합니다. 설계하세요:

```
격리:
  수집 경로에서 테넌트 주입 — 팀별 Collector/에이전트가 X-Scope-OrgID
  (또는 테넌트 라벨)를 강제. 앱이 자기 신고하게 두지 않습니다(위조 방지)
  쿼리: Grafana 데이터소스가 테넌트 스코프 — A팀 대시보드는 A만

쿼터 (03·22의 격벽):
  활성 시계열/테넌트: 예) 기본 30만, 초과 시 신규 시계열 거부+알림
  수집률·쿼리 동시성·쿼리 범위(기간) 한도
  ★ 한도 도달의 UX 설계: "거부됐습니다"가 아니라
    "한도 도달 — 카디널리티 리포트 링크 + 상향 요청 절차" (47의 제품 사고)

귀속 (22의 showback):
  테넌트별 시계열 수·수집률·쿼리 비용 대시보드 → 팀에 공개
  월간 리뷰의 데이터

정책 점검 질문:
  □ 한 팀의 라벨 폭발이 이웃 팀 쿼리를 느리게 할 수 있는 경로가 남았나요?
  □ 쿼터 상향의 절차가 있나 (없으면 격벽이 그림자 IT를 만듭니다)
  □ 공용 메트릭(클러스터 수준)은 어느 테넌트 소유인가요?
```

## 3. 규모별 판단 지도 — 최종 산출물

세 조직 시나리오에 아키텍처를 배정하고 근거를 써라(cncf 48의 3층으로):

```
A. 클러스터 2개(prod·stage), 보존 30일, 플랫폼 겸직 1명
<답> 규모 1.5 — 단일 스택 × 2 + (보존 요구가 로컬 한계 근처면) AMP 검토.
  Thanos는 과잉: 부품 5종의 운영이 겸직 1명에게 정당화 안 됨.
  "층은 필요가 정당화한다" (07·46의 반복)

B. EKS 12개(3리전), 보존 13개월, AWS 올인, 플랫폼 3명
<답> 규모 2 — 각 클러스터 08 유지 + AMP 워크스페이스 집약(리전별 또는
  통합) + AMG. 관리형 우선(09): 13개월×12클러스터의 자체 스토리지·
  compactor 운영을 3명이 지는 것보다 샘플 요금이 쌉니다 — 22의 방정식으로
  계산해 검증(시계열 수×빈도). Thanos로 넘어갈 재평가 조건을 ADR에:
  "멀티클라우드 확장 또는 AMP 요금이 자체 운영비의 X배 초과 시"

C. 온프레+3클라우드 60클러스터, 시계열 5천만, 관측 전담 5명, 테넌시 필수
<답> 규모 3 — Thanos(기존 Prometheus 자산 활용·점진) 또는 Mimir(테넌시
  1급·중앙 운영). 온프레 포함이라 AMP 단독 불가. 5천만 시계열이면
  쿼터·격벽 없이는 03 사고가 조직 규모로 — 테넌시가 선택이 아닌 필수.
  전담 5명이 "설치≠운영"(compactor·스토리지·업그레이드)을 감당하는 조건.

지도의 공통 각주 (이 파트의 결론):
  어느 규모든 — 02의 구조화, 03의 라벨 규율, 05의 지도, 08의 수집 체계,
  10·21의 알림 규율, 12의 상관 규약, 22의 비용 체계, 23의 동선은 불변.
  규모가 바꾸는 것은 저장·쿼리 토폴로지뿐 — ★ 기본기가 이식성입니다.
```

## 정리

- HA·dedup: replica 2벌 수집 + Query의 replica-label 병합 — 구멍의 상호 보완 (비용은 등급별로)
- 테넌시 설계: 격리(주입 강제)·쿼터(격벽+UX)·귀속(showback) — 03 사고의 조직 규모 방어
- 판단 지도: 규모 1(단일)/2(AMP 집약)/3(Thanos·Mimir) — 재평가 조건을 ADR로
- **★ production 수료: 규모가 바꾸는 것은 토폴로지뿐, 기본기(규율·규약·동선)는 불변 — 그것이 이식성입니다**
