# 이론 — 비용 방정식, 관측의 관측, 레버리지 체계, 가치 평가, 조직 장치

> **🌱 17세 눈높이 비유: 가족 휴대폰 요금제의 관리**
> - **방정식** = 요금 = 데이터량 × 단가 — 각자(신호별)의 사용량 구조를 알아야 줄일 곳이 보임
> - **관측의 관측(사용량 앱)** = 요금 고지서(월 1회, 늦음)가 아니라 실시간 사용량 앱으로 — "동생이 오늘 5GB를 썼네?"(급증 알림)
> - **레버리지 순서** = ① 와이파이 쓰기(소스에서 데이터 안 쓰기 = 수문) ② 영상은 저화질로(계층·해상도) ③ 이월 데이터 정리(보존)는 효과 미미
> - **가치 평가** = 결제해 놓고 안 보는 구독(안 쓰는 신호)을 해지 — 아낀 돈으로 정말 쓰는 것을 업그레이드(정렬)
> - **공유지의 비극** = 가족 공유 데이터를 아무도 아껴 쓰지 않음 — 각자 사용량을 보이게 하고(귀속) 예산을 합의

---

## 1. 신호별 비용 방정식 (계산 가능한 형태로)

```
로그:
  비용/월 ≈ GB/일 × 30 × ingest단가 + GB/일 × 보존일 × 저장단가(평균 잔존)
           + (OpenSearch면) 색인 계수 × 노드 비용
  지배 변수: 볼륨 — 그리고 볼륨의 지배자는 소음(debug·헬스체크·중복)

메트릭:
  Prometheus 자체: 활성 시계열 × ~수 KB 메모리 + 디스크
  AMP: 시계열 × (2.59M초/scrape간격) × 샘플 단가 (14의 계산)
  CW: 커스텀 메트릭(디멘션 조합) 수 × 단가 (13)
  지배 변수: 카디널리티 (03의 곱셈)

트레이스:
  요청/s × 샘플율 × 평균 span 수 × span 크기 × 보존
  지배 변수: 샘플율 (그리고 span 남발 — 11의 함정 4)

프로파일:
  대상 프로세스 수 × 주기 × 스택 크기 × 보존 (20)

★ 공통: 볼륨×단가. 단가 협상(도구 교체)보다 볼륨 통제가 먼저입니다
```

## 2. 관측의 관측 — 자기 계측 카탈로그

```
[볼륨 층]
  로그: Fluent Bit fluentbit_output_proc_bytes_total (경로별!)
       CW IncomingBytes (그룹별 — 13) / Loki 배포 시 loki_ingester_*
  메트릭: prometheus_tsdb_head_series (총량)
         topk(10, count by (__name__)({__name__=~".+"})) (범인 순위)
         scrape_samples_scraped (타깃별 — 폭발 조기 발견)
  트레이스: Collector otelcol_receiver_accepted_spans (수집량)

[건강 층 — 유실·적체]
  fluentbit_output_dropped_records / retries_failed (06)
  otelcol_exporter_send_failed_* (11·16)
  prometheus_remote_storage_samples_failed/dropped (14)
  큐·버퍼 깊이들 (07의 계단 알림)

[비용 추정 층]
  위 볼륨 × 단가를 recording rule로 → "일일 추정 비용" 시계열
  → 대시보드 + 급증 알림 ("어제보다 3배" — 청구서 3주 전에)

★ 이 세 층이 "관측 플랫폼의 RED/USE"다 — 09의 방법론을 자신에게
```

## 3. 통제 수단 카탈로그 (레버리지 순서로)

```
① 수문 (만들지/보내지 않기) — 조각들의 집결
  앱: 레벨 규율·로그 rate-limit·span 절제 (02·11)
  수집기: grep/필터 (06), metricRelabelings·sampleLimit (08),
         head 샘플링 (11), L7 선별 (19)
  검증: 수문 걸기 전후의 볼륨 메트릭 비교 (효과의 정량화)

② 계층·라우팅 (가치별 목적지)
  tag 라우팅(06)·copy(07): 핫 조사/보안·감사/아카이브 분리
  writeRelabelConfigs(14): 원격엔 장기 가치만
  ISM·retention(18·13): 저장소 안의 노화

③ 보존·해상도
  retention 짧게, 다운샘플링(장기 추세는 5m 해상도로 충분),
  scrape 간격 재검토(15s가 다 필요한가 — 14의 계산)

④ 구조 (큰 수술)
  저장소 재배정(18의 문진 — 안 맞는 도구에서 맞는 도구로)
  중복 수집 제거(같은 메트릭을 CW와 AMP 양쪽에? — 16의 분배 재설계)
```

## 4. 가치 평가 — 사용 추적과 폐기 절차

```
사용의 증거:
  대시보드: 패널 조회 수 (Grafana 분석)
  쿼리: 저장소 쿼리 로그에서 메트릭/필드 사용 빈도
  알림: 발화·대응 이력 (10의 통계)

절차 (분기):
  ① 미사용 후보 목록 (90일 무사용 메트릭·패널·로그 스트림)
  ② 등급 보정: 감사·규정·희귀 사고용은 "사용 빈도" 면제 (답 못 하면의
     비용으로 평가 — 06의 등급별 설계)
  ③ 폐기 공지 → 유예 → 수문에서 차단 (저장소에서 지우는 게 아니라
     들어오는 것을 끊습니다 — 13의 교훈)
  ④ 아낀 예산의 재투자 결정 (부족한 커버리지로 — 정렬!)

★ 22의 목표 문장: "모든 신호는 답할 질문이 있고,
  모든 질문은 답할 신호가 있다" — 비용과 커버리지의 동시 최적
```

## 5. 조직 장치

```
귀속(showback): 네임스페이스·팀 라벨 기반 볼륨·비용 배분 대시보드
  → "우리 팀이 로그 비용의 40%"가 보이면 행동이 바뀝니다
예산·견적: 신규 대량 신호(새 서비스 대량 로그·고빈도 메트릭)는 사전 견적
  (03 사고의 예방 — 라벨 심사와 짝)
가드레일 강제: sampleLimit(08)·쿼터·정책 엔진(cncf 32 — 예: 라벨 수 제한
  정책) — 리뷰가 놓친 것을 시스템이
리뷰 루프: 월간 비용 리뷰(급증 조사·수문 효과 확인) + 분기 가치 평가(4절)
→ cncf 47: 관측 플랫폼도 제품 — 비용 효율이 제품 지표의 하나
```

## 6. 소스/도구에서 확인하기

- 각 도구의 자기 메트릭 문서 (Fluent Bit·Collector·Prometheus·Loki)
- OpenCost(cncf 45): K8s 비용 배분의 일반 도구 (관측 비용 귀속에도)
- 13·14의 요금 계산, 18의 문진 — 이 모듈의 재료들

| 공통 방정식? | 볼륨 × 단가 — 지배 변수는 통제 안 된 증식(소음·카디널리티·전수) |
