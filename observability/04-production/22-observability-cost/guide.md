# 학습 가이드 — 조각들이 체계가 되는 순간

## 이 모듈의 위치 — 흩어진 교훈의 종합

파트를 관통해 온 비용의 조각들:

```
03·08: 카디널리티 = 메모리·요금 (라벨은 곱셈, 수문·sampleLimit)
06: 로그 수문 (grep 필터 = 매달 돈, 13에서 실증)
07·13·18: 계층화 (copy로 목적지 분리, CW+S3, ISM)
11·17: 샘플링 (head 볼륨 통제 + tail 가치 선별)
12·17·18: 색인의 절제 (라벨·annotation·매핑 — 네 번의 반복)
13: 요금의 물리 (ingest ≫ 저장 — 레버리지는 소스에)
```

이 모듈은 이것들을 **반복 가능한 체계**(방정식→측정→통제→평가→조직)로 묶습니다. 새 기술이 아니라 운영 규율의 모듈입니다.

## 신호별 비용 방정식 — 한 장

```
로그   ≈ 볼륨(GB/일) × [ingest 단가 + 보존일 × 저장 단가 + 색인 계수]
메트릭 ≈ 활성 시계열 × scrape 빈도 × 샘플 단가 (+카디널리티의 메모리)
트레이스 ≈ 요청 수 × 샘플 비율 × span 수 × 크기
프로파일 ≈ 대상 수 × 주기 × 스택 다양성

공통 구조: 볼륨 × 단가 — 그리고 볼륨의 지배 변수는 언제나
  "통제 안 된 증식"(카디널리티·debug 로그·전수 샘플링)
```

## 관측의 관측 — 왜 자기 계측이 먼저인가

```
통제하려면 보여야 합니다 (01의 원리를 관측 자신에게):
  로그: 그룹/네임스페이스별 볼륨 추세 (급증 = 02의 폭주 사고 조기 경보)
  메트릭: 시계열 수·상위 메트릭 (03의 폭발 조기 경보)
  파이프라인: 드롭·재시도·버퍼 (06·07의 유실 가시화)
  비용: 추정치의 대시보드화 (청구서 전에 아는 것)

이 대시보드가 없는 조직의 공통점: 비용 문제를 청구서(월 1회, 3주 늦은
신호)로 발견합니다 — 13의 사고("워크로드를 넘던 날")의 근본 원인
```

## 레버리지 순서 — 어디부터 손대나

```
① 수문 (소스에서 차단) — 최대 레버리지
   안 만들기(02 레벨 규율·앱 rate-limit) > 안 보내기(06 필터·08 relabel·
   11 샘플링) — 이후 모든 단계의 비용이 사라짐
② 계층화 (싼 곳으로 라우팅)
   가치·패턴별 목적지 분리 (18의 문진: 검색 필요 없으면 S3)
③ 보존 (짧게)
   이미 들어온 것의 저장만 절감 — 최소 레버리지 (13의 교훈)
④ 해상도 (성기게)
   scrape 간격·프로파일 주기·다운샘플링 — 정밀도와의 협상

순서를 거꾸로 타는 조직이 많습니다 (보존부터 줄임 — 효과 미미)
```

## 가치 평가 — 삭감이 아니라 정렬

```
질문: "이 신호로 답한 질문이 최근 90일에 있었는가"
  대시보드 조회 수·쿼리 로그·알림 발화 이력로 추적 가능
  없다면: 폐기 후보 (01의 원칙 — 답할 질문이 없는 신호는 안 모읍니다)
  단: 드물지만 치명적 질문(감사·사고 조사)의 신호는 사용 빈도가 아니라
      "답 못 하면의 비용"으로 평가 — 등급별 판단 (06의 등급)

목표는 예산 삭감이 아니라 정렬:
  안 쓰는 신호를 끊어 → 부족한 신호(트레이스 커버리지? 프로파일?)에 투자
  → 같은 예산의 조사력 최대화
```

## 조직 장치 — 공유지의 비극 방지

```
관측 비용은 공유지가 되기 쉽습니다 (모두가 넣고 아무도 책임 안 짐)
  팀별 귀속: 네임스페이스·라벨 기반 비용 배분 가시화
  예산·리뷰: 월간 비용 리뷰(급증 팀과 대화), 신규 대량 신호는 사전 견적
  가드레일: sampleLimit·쿼터·정책(cncf 32로 강제 가능)
→ cncf 47의 "제품으로서의 플랫폼" — 관측 플랫폼의 비용도 제품 지표
```
