# 23 — 장애 대응: 관측이 뒷받침하는 온콜의 동선

> 이 파트가 지은 모든 것 — 신호(01~05)·파이프라인(06~18)·심층 도구(19~20)·SLO 알림(21) — 은 결국 **장애의 순간**을 위해 존재합니다. 이 모듈은 그 순간의 운영을 설계합니다: 장애 대응의 표준 동선(감지→트리아지→조사→완화→해소), 역할 분담(IC — 사건 지휘자·조사·소통의 분리), **runbook as code**(알림에 실려 오는 그 링크의 내용물 — 낡지 않게 유지하는 법), 포스트모템(비난 없는 — 시스템을 고치는 회고), 그리고 **게임데이**(모의 장애로 동선·도구·사람을 리허설 — "있다"와 "쓰인다"의 간극은 리허설만이 드러냅니다, 09·12의 숙제). 온콜의 지속 가능성(로테이션·부담 관리)까지가 이 모듈의 범위입니다.

## 학습 목표

1. 장애 대응의 표준 동선과 각 단계에서 여는 신호(파트 전체의 종합)를 체화합니다
2. 역할 분담(IC·조사·소통)과 심각도 분류·에스컬레이션을 설계합니다
3. runbook as code — 좋은 runbook의 구조와 낡지 않는 유지 체계를 만듭니다
4. 비난 없는 포스트모템의 구조와 액션 아이템의 수명 관리를 압니다
5. 게임데이를 설계·운영해 동선·배선·사람을 리허설합니다
