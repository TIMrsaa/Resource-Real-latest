# Lab 01 — 황금 경로 설계와 IDP 통합

> 도구 설치가 아니라 **설계 훈련**입니다. 실제 개발팀의 니즈에서 출발해 황금 경로를 설계하고, 41·42·46이 그 경로를 어떻게 실현하는지 조립하며, "pave not fence"의 균형을 연습합니다.

## 1. 개발자 니즈에서 출발 (제품 사고의 시작)

플랫폼을 만들기 전에 **개발자가 뭘 힘들어하는지** 조사합니다(가상 인터뷰 결과):

```
개발자 인터뷰 요약:
  "새 서비스 시작할 때마다 반나절 — 레포·CI·Dockerfile 복붙"
  "DB 하나 받으려면 인프라팀에 티켓, 며칠 대기"
  "관측 설정을 자꾸 잊어서 장애 때 로그가 없음"
  "배포 파이프라인이 팀마다 달라서 옮기면 헷갈림"
  "K8s YAML은 무섭습니다 — 뭘 잘못 쓸까 봐"

→ 공통 고통: 시작의 반복 작업, 인프라 대기, 잊는 모범사례, 불일치
→ 이것이 황금 경로가 풀 문제 (개발자 언어로)
```

**핵심** — 플랫폼을 "우리가 멋지다고 생각하는 것"이 아니라 **개발자의 실제 고통**에서 설계합니다(제품 사고, theory 5절).

## 2. 황금 경로 설계

위 고통을 푸는 "새 마이크로서비스" 황금 경로를 설계합니다:

```
황금 경로: "새 서비스 만들기"
  개발자 입력: 서비스명, 팀, 언어(Go/Node/Python), DB 필요 여부
  자동 생성:
    ✓ 레포 (표준 구조·Dockerfile·health 엔드포인트)
    ✓ CI 파이프라인 (빌드·테스트·스캔·서명 — cicd 21)
    ✓ 관측 (Prometheus 스크레이프·OTel·대시보드 — 자동, 잊을 수 없음)
    ✓ 배포 (ArgoCD Application — GitOps 14)
    ✓ DB (선택 시 Crossplane Claim — 41)
    ✓ 메시 (사이드카 자동 주입 — 24, 선택)
    ✓ 카탈로그 등록 (42)

설계 원칙 적용:
  안전한 기본값: 관측·보안이 자동으로 켜짐 (개발자가 잊어도)
  80% 케이스: 대부분 서비스가 이 경로로 충분
  escape hatch: 특수 요구는 경로를 벗어나 커스텀 가능 (강제 아님)
```

## 3. 41·42·46이 경로를 실현 (통합)

이 황금 경로가 배운 도구들로 어떻게 구현되나:

```
개발자가 Backstage(42)에서 "새 서비스" 클릭
  ↓
Software Template(42 lab-02)이 실행:
  1. fetch:template → 표준 스켈레톤 (레포 구조)
  2. publish:github → 레포 생성
  3. (DB 선택 시) kubernetes:apply →
       AppDatabase Claim (41 lab-02) → Crossplane이 DB 프로비저닝
  4. ArgoCD Application 생성 (46 GitOps)
     → sync-wave로 관측·메시가 자동 적용 (46 lab-02)
  5. catalog:register → Backstage 카탈로그 (42)
  ↓
몇 분 뒤: 레포·CI·DB·관측·배포·메시가 준비된 서비스
```

**관찰** — 41(인프라 API)·42(포털·템플릿)·46(플랫폼 층)이 각자의 역할로 하나의 황금 경로를 실현합니다. 개발자는 이 통합을 몰라도 되고, "새 서비스" 버튼만 누릅니다 — 인지 부하가 플랫폼으로 흡수됐습니다.

## 4. pave not fence — 균형 연습

황금 경로를 강제로 만들면 어떻게 되나, 시나리오로 봅니다:

```
시나리오: ML 팀이 특수 GPU·큰 이미지·긴 시작시간 서비스가 필요

강제(fence) 접근:
  "모든 서비스는 이 템플릿만" → ML 팀이 맞출 수 없음
  → ML 팀이 플랫폼 우회, 자기들끼리 따로 구축 (그림자 IT)
  → 플랫폼 분열, 불신

pave 접근:
  기본 경로는 80%(일반 서비스)를 덮음
  ML 팀엔 → escape hatch (템플릿 커스텀) 또는
            ML 전용 황금 경로를 추가 (경로를 넓힘)
  → ML 팀도 플랫폼 안에서, 표준의 이점(관측·배포)은 유지
```

**핵심** — 황금 경로는 **매력**이어야 합니다(쉽고 빠르니 자연히 선택). 강제하면 우회를 부릅니다(41의 새는 추상, 42의 감옥이 된 경로의 반복). 예외를 허용하되 표준의 이점은 유지하는 균형이 설계의 기술입니다.

## 5. 경로를 넓히는 것도 설계 (지속)

```
플랫폼은 끝나지 않습니다 (제품):
  ML 팀 요구 → ML 황금 경로 추가
  새 언어 요구 → 템플릿 확장
  새 규정 준수 → 모든 경로에 정책(32) 추가 (한 곳 수정, 전체 적용 — 41 Composition의 힘)

★ 황금 경로는 살아있는 제품
  개발자 니즈가 바뀌면 경로도 진화
  → 이것이 "제품으로서의 플랫폼"의 일상 (lab-02)
```

## 6. 정리

- 황금 경로는 **개발자의 실제 고통**에서 설계 (제품 사고)
- 41(인프라 API)·42(포털·템플릿)·46(플랫폼 층)이 하나의 경로를 실현
- 안전한 기본값(관측·보안 자동), 80% 케이스 + escape hatch
- **pave not fence**: 매력으로 선택하게, 강제하면 우회(그림자 IT)
- 경로를 넓히는 것도 지속 설계 — 플랫폼은 살아있는 제품
- **★ 인지 부하가 개발자 버튼 하나 뒤로 흡수됨 — 41·42·46의 통합이 이것을 위해**
