# 학습 가이드 — Graduated 밀집 지대를 층으로 자르기

## 왜 이 카테고리에 Graduated가 몰려 있나

CoreDNS, Envoy, Cilium, Istio, Linkerd — 네트워킹은 CNCF에서 졸업생이 가장 밀집한 동네입니다. 이유는 구조적입니다: **네트워크는 모든 워크로드가 지나는 공유 기반**이라 표준화 압력이 가장 세고(전원이 쓰니 전원이 기여), 동시에 커널·클라우드와 맞닿아 있어 한 회사가 독점하기 어렵습니다(중립 재단의 가치가 최대 — 01). 그 결과 이 지도는 "뭘 쓸까"보다 "**어떤 층 조합으로 쓸까**"의 지도입니다.

## 층의 감각 — 패킷의 여정에 프로젝트를 얹기

eks 18에서 패킷을 따라갔던 그 경로에 이 지도의 프로젝트들을 얹으면:

```
Pod가 생깁니다        → CNI가 IP·인터페이스를 만듭니다        (Cilium/Calico/Flannel/vpc-cni)
이름을 부릅니다       → CoreDNS가 IP로 바꿉니다               (Service 디스커버리)
Service로 갑니다      → kube-proxy(iptables) 또는 eBPF가 라우팅
밖에서 들어옵니다     → 인그레스/게이트웨이 (Envoy 기반들, Gateway API)
서비스끼리 암호화·관찰 → 메시 (Istio/Linkerd/Cilium Mesh — eks 20)
```

로고가 수십 개여도 층은 다섯입니다. 같은 층 안에서만 비교가 성립합니다 — 03의 교훈이 여기서도 첫 규율입니다.

## eBPF — 이 지도의 지각 변동

전통 K8s 네트워킹은 iptables 규칙 체인(Service 하나당 규칙 여러 개, 선형 탐색) 위에 서 있습니다 — 수천 Service에서 병목이 됩니다. eBPF는 커널 안에 안전하게 프로그램을 심는 기술이고, Cilium은 그것으로 CNI·kube-proxy 대체·NetworkPolicy·관찰(Hubble)을 전부 다시 지었습니다 — 해시맵 조회가 규칙 체인을 대체합니다. "Cilium이 인기"라는 현상의 뿌리가 이 구조 전환이고, lab-02에서 직접 만집니다. (Cilium 심층은 22에서 — 여기서는 지도와 시식.)

## Envoy — 로고 뒤에 숨은 공용 부품

이 지도에서 가장 중요한 통찰 하나: Istio의 사이드카도, Contour·Emissary 인그레스도, 수많은 API 게이트웨이도 **속은 Envoy**입니다. Envoy는 동적 설정 API(xDS)를 가진 L7 프록시 엔진이고, 그 위에 "설정을 누가 만들어주느냐"만 다른 건축물들이 서 있습니다. 로고 벽에서 Envoy 계보를 그릴 수 있으면 이 카테고리의 절반이 정리됩니다(Envoy 심층은 23에서).
