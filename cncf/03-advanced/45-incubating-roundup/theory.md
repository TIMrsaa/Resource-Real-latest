# 이론 — 범주별 라운드업, 자리매김, 성숙도, 항해술

> **🌱 17세 눈높이 비유: 거대한 쇼핑몰의 층별 안내도**
> - **쇼핑몰(CNCF 랜드스케이프)** = 수백 개 매장, 매달 새 매장 오픈
> - **가게를 다 외우기(불가능)** = 매장 300개를 다 기억? 무리, 새 매장은 계속 생김
> - **층별 안내도(01~10 축)** = "3층은 의류, 4층은 식당" — 새 매장이 생겨도 "아 이건 4층(식당) 계열"로 위치
> - **이미 아는 가게와 비교** = "이 카페는 스타벅스(Prometheus)의 저가형 버전(Thanos)이구나"
> - **핵심** = 다 외우는 게 아니라 **안내도(축)에 놓는 법** — 그러면 새 매장도 당황 없이 위치

## 1. 관측 축 (06·11·12) — Prometheus 주변

```
문제: Prometheus(11)는 단일 노드·단기 저장 → 대규모·장기가 약점
해법 프로젝트들 (전부 "Prometheus의 확장"):
  Thanos     — Prometheus에 장기 저장·글로벌 쿼리·다운샘플링 (사이드카)
  Cortex     — 멀티테넌트·수평 확장 Prometheus (통합형)
  Mimir      — Cortex 계보, 대규모 메트릭 (Grafana Labs)
  → 셋 다 "11의 카디널리티·장기 저장 벽"을 푸는 다른 접근

로그·기타:
  Loki       — "로그의 Prometheus" (라벨 기반, 인덱스 최소화)
  Fluentd/Bit(다룸) — 로그 수집
  Pixie      — eBPF 기반 자동 관측 (27의 eBPF 응용)
  OpenCost   — 비용을 관측 (리소스→돈, FinOps)

★ 자리매김: 전부 06(관측 가능성)의 확장, 11 Prometheus를 중심에 두고 방사
```

## 7. 성숙도와 채택 판단 (08 종합)

```
CNCF 성숙도 단계:
  Sandbox     — 초기·실험 (프로덕션 신중, 트렌드 관찰)
  Incubating  — 검증 진행 (채택 사례 보고 신중히)
  Graduated   — 성숙 (프로덕션 후보)

채택 체크리스트 (08·39·40의 반복):
  □ 어느 축의 문제를 푸나 (지도에 위치)
  □ 이미 아는 무엇의 대안·보완인가
  □ 성숙도 + 실제 채택 사례 + 커뮤니티 활성
  □ 대안 대비 명확한 이점이 있나
  □ "설치의 쉬움 ≠ 운영의 쉬움" — 운영 비용은?
  □ 관리형·기존 도구로 충분하지 않은가
  → 신기술 매력이 아니라 문제-해결 적합성으로

★ Sandbox를 프로덕션에 성급히 넣지 말 것
  하지만 트렌드는 관찰 (다음 Graduated가 여기서 나옵니다)
```

## 8. 항해술 요약 — 새 프로젝트를 만나면

```
1. 축 식별: 관측·네트워크·스토리지·보안·런타임·플랫폼·멀티클러스터 중?
2. 연결: 이미 아는 어느 프로젝트의 대안·보완·확장인가요?
3. 존재 이유: 무엇을 좁혀·다르게 푸나요? (05의 "범위를 좁히는 것도 설계")
4. 성숙도: Sandbox/Incubating/Graduated? 채택 사례?
5. 판단: 우리 문제에 맞나요? 대안보다 나은가요? 운영 감당되나요?
→ 이 5단계로 어떤 새 프로젝트든 지도에 놓습니다
```
