# Lab 02 — 새 프로젝트 항해술과 채택 판단

> 이 커리큘럼이 끝난 뒤, 회원님은 반드시 **처음 보는 프로젝트**를 만납니다(랜드스케이프는 계속 자라므로). 이 랩은 그때 스스로 조사하고 판단하는 재현 가능한 절차를 줍니다 — 05의 항해술을 실전 워크플로로.

## 1. 새 프로젝트 5분 스캔 절차

낯선 프로젝트를 만났을 때, 이 순서로 5분 안에 지도에 놓습니다:

```
① README/홈페이지 첫 문단 (30초)
   "무엇을 하는가"를 한 문장으로 뽑습니다
   → 대부분 프로젝트가 첫 문단에 "X를 위한 Y"라고 밝힙니다

② 축 식별 (30초)
   관측/네트워크/스토리지/보안/런타임/CI·CD/플랫폼/멀티클러스터?
   → 01~10의 어느 축인가

③ 연결 찾기 (1분)
   "이건 이미 아는 무엇과 비슷/다른가?"
   → advanced에서 배운 프로젝트에 붙입니다

④ 존재 이유 (1분)
   "기존 것으로 안 되나요? 무엇을 좁혀·다르게 푸나요?"
   → 05의 "범위를 좁히는 것도 설계" 관점

⑤ 성숙도·채택 (2분)
   CNCF 단계(Sandbox/Incubating/Graduated)?
   GitHub 활성(최근 커밋·이슈·기여자)?
   실제 채택 사례(ADOPTERS.md, 케이스 스터디)?
   → 08의 "커뮤니티·채택으로 성숙도 판단"
```

## 2. 예시 적용 — 가상의 새 프로젝트 "FooMesh"

처음 보는 "FooMesh"를 만났다고 합시다. 절차 적용:

```
① 첫 문단: "FooMesh는 eBPF 기반 사이드카 없는 서비스 메시"
② 축: 네트워크·서비스 메시 (24·27)
③ 연결: "Cilium(27)의 메시 기능, Istio ambient(24)와 같은 사이드카리스 흐름"
④ 존재 이유: "사이드카 오버헤드(24)를 eBPF로 없앰 — Istio 사이드카의 대안"
⑤ 성숙도: (조사) Sandbox면 → 관찰만, 프로덕션은 검증된 Cilium/Istio

결론: "24·27 축의, 사이드카리스 메시 흐름의 신생 대안.
      개념은 이해되나 성숙도 확인 전엔 프로덕션 보류,
      Cilium/Istio ambient가 이미 그 방향이니 비교 관찰"
```

**핵심** — 처음 봤지만 당황하지 않았습니다. advanced에서 배운 24·27이 있어 "아는 것의 변주"로 즉시 위치시켰습니다. 이것이 이 커리큘럼이 준 능력입니다.

## 3. 채택 판단 체크리스트 (실전)

프로젝트를 실제로 도입할지 결정할 때:

```
□ 문제 적합성
  우리의 실제 문제를 푸나요? (신기술 매력 아님)
  이미 쓰는 도구로 안 되나요?

□ 성숙도
  Graduated > Incubating > Sandbox
  프로덕션이면 Graduated·검증된 Incubating 우선
  Sandbox는 관찰·실험용

□ 커뮤니티·지속성
  활발한 커밋·다양한 기여자(한 회사 의존 위험)
  벤더 중립? (한 회사가 버리면?)

□ 운영 비용 (39·40·41·42의 반복)
  "설치의 쉬움 ≠ 운영의 쉬움"
  업그레이드·장애 대응·전문성 확보 가능한가
  관리형 대안이 있나

□ 이탈 비용(lock-in)
  나중에 걷어내기 쉬운가
  표준(06·03·40) 기반이면 이식성↑
```

## 4. 계속 배우는 법 — 커리큘럼 이후

```
정보 소스:
  CNCF Landscape (landscape.cncf.io) — 축·성숙도 탐색
  CNCF Blog·TAG(Technical Advisory Group) — 심화·트렌드
  KubeCon 발표 — 실전 사례
  각 프로젝트 CNCF 졸업/승격 뉴스 — 성숙 신호

습관:
  새 프로젝트 = 5분 스캔으로 지도에 (2절)
  깊이는 필요할 때만 (모두 깊게 X)
  contributor(49~50)로 가려면 관심 프로젝트를 골라 깊이

★ 이 커리큘럼은 "다 아는 것"이 아니라
  "계속 배울 수 있는 지도와 근육"을 줍니다
```

## 5. advanced 트랙 종합 회고

```

36~40: 데이터 (스토리지·DB·메시징 — 09의 스테이트풀 판단)
41~44: 플랫폼 (Crossplane·Backstage·Knative·Karpenter)
45: 지도 완성 (라운드업·항해술)

관통 주제:
  - 표준이 이식성을 만듭니다 (06·03·40)
  - 시스템 vs 오케스트레이터 (39·40)
  - 자동화가 물리를 숨기지만 없애지 않습니다 (37·39·41·43·44)
  - 설치의 쉬움 ≠ 운영의 쉬움 (05·39·40·41·42)
  - 관리형 우선, 자체는 역량+조건 (09 전체)
  - 힘엔 규율이 따릅니다 (41 인프라·42 문화·44 중단내성)
→ 이 원리들이 production(46~48)에서 종합됩니다
```

## 정리

- 새 프로젝트 5분 스캔: 첫 문단→축→연결→존재이유→성숙도
- 처음 봐도 "아는 것의 변주"로 위치 (advanced가 준 연결점)
- 채택 판단: 문제 적합성·성숙도·커뮤니티·운영 비용·이탈 비용
- 커리큘럼 이후: Landscape·KubeCon·CNCF 뉴스로 계속, 깊이는 필요할 때
- **★ 이 커리큘럼은 "다 아는 것"이 아니라 "계속 배울 지도와 근육"을 줍니다 — 05의 완성**
