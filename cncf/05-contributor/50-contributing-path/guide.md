# 학습 가이드 — 마지막 모듈, 첫 걸음

## 이 커리큘럼이 여기로 온 이유

돌아보면 전부 이 순간의 준비였습니다:

```
01~10 (지형): 생태계 전체를 조망 → 어디에 기여할지 고를 안목
11~45 (심층): 프로젝트들의 내부 동작 → 기여할 기술 기반
46~48 (판단): 조립·운영·선택 → 실무자의 관점 (좋은 이슈의 원천!)
49 (거버넌스): 누가 어떻게 결정하나 → 기여가 겉돌지 않을 지도
50 (지금): 실제로 걷기
```

자격증은 "알고 있음"의 증명이지만, 기여는 "생태계를 만들고 있음"의 증명입니다. 이 커리큘럼의 졸업장은 머지된 PR, 정리된 이슈, 도움받은 다른 사용자입니다.

## 기여에 대한 가장 큰 오해 둘

```
오해 ①: "기여 = 코드, 그것도 대단한 코드"
현실: 가장 필요한 기여의 다수가 코드 밖:
  문서 개선 (커리큘럼에서 헤맨 그 부분!)
  이슈 재현·트리아지 (묻힌 버그 리포트에 재현 절차 붙이기)
  좋은 버그 리포트 (운영에서 만난 문제를 제대로 보고)
  리뷰·테스트·번역
→ 코드는 여러 기여 형태 중 하나

오해 ②: "나는 아직 부족해"
현실: 45개 모듈을 지나온 지금, 회원님은
  - 프로젝트의 내부 구조를 알고 (theory들)
  - 실제 운영 함정을 알고 (pitfalls들)
  - 뭐가 문서에 없어서 헤맸는지 압니다
→ "실무에서 헤맨 경험"이야말로 프로젝트가 가장 원하는 입력
```

## 첫 기여의 전략 — 작게, 정찰 후에

49의 교훈(석 달 PR 사고)을 전략으로:

```
1. 대상 선정: 관심 × 역량 × 거버넌스 건강 (49 lab-02의 정찰 시트)
2. 잠복 관찰: 슬랙 가입, 회의록 읽기, 이슈 흐름 보기 (1~2주)
3. 작은 시작: good first issue, 문서 오타, 이슈 재현
4. 신뢰 축적: 꾸준한 작은 기여 → 리뷰어들이 이름을 기억
5. 확장: 더 큰 이슈 → 설계 논의 참여 → ladder
```

## 지속 가능성 — 번아웃 없이

기여는 단거리가 아니라 생활입니다:

```
- 주당 몇 시간이라도 꾸준히 > 몰아서 태우고 사라지기
- 관심 없는 것 억지로 X → 커리큘럼에서 재밌던 영역으로
- 거절·정체를 개인적으로 받지 않기 (49 — 합의 비용)
- 받는 것도 기여의 일부: 리뷰에서 배우고, 커뮤니티를 즐기기
```

## 마지막 안내

이 모듈의 lab은 "따라 하면 끝"이 아니라 **실전 체크리스트**입니다. lab-01의 각 단계를 실제 프로젝트에 실제로 수행하는 것 — 그것이 이 커리큘럼의 최종 과제이자, 끝나지 않는 시작입니다.
