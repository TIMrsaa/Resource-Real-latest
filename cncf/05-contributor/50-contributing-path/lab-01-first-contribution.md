# Lab 01 — 첫 기여 실전: 대상 선정부터 첫 PR까지

> 이 랩은 시뮬레이션이 아니라 **실전 체크리스트**입니다. 각 단계를 실제 프로젝트에 실제로 수행하세요. 여기서부터는 커리큘럼이 아니라 회원님의 기여 이력이 만들어집니다.

## Step 1 — 대상 선정 (49의 정찰 활용)

```
□ 커리큘럼에서 가장 재밌던 모듈 3개를 적어라
  (그 영역이 관심 축 — 예: 11 관측, 22 eBPF, 16 GitOps...)

□ 각 영역의 프로젝트에 49 lab-02 정찰 시트를 적용:
  - GOVERNANCE / CONTRIBUTING / ladder 존재?
  - 메인테이너 다양성?
  - good first issue가 실제로 있고 최근 처리되나요?
  - 슬랙·회의가 살아 있나요?

□ 하나로 좁혀라 (여러 곳에 발 걸치지 말 것 — 신뢰는 한 곳에서 쌓입니다)
```

## Step 2 — 잠복 관찰 (1~2주)

```
□ 프로젝트 슬랙(CNCF Slack: slack.cncf.io) 가입, 채널 참여
□ 최근 회의록 2~3개 읽기 (로드맵·진행 중 논의 파악 — 49 사고 예방)
□ 최근 머지된 PR 5개 훑기 (어떤 PR이 잘 통과되나, 리뷰 스타일)
□ 이슈 목록 훑기 (뭐가 고통인가, good first issue 후보 눈여겨보기)
□ CONTRIBUTING.md 정독 (DCO? 테스트 실행법? 개발 환경?)
```

## Step 3 — 개발 환경 (코드 기여 대비)

```bash
# 예시 (프로젝트마다 CONTRIBUTING.md 참고)
git clone https://github.com/<org>/<project>
cd <project>

# 빌드·테스트가 로컬에서 도는지 확인 (기여의 물리적 전제)
make build && make test    # 또는 프로젝트의 방식

# DCO 서명 습관화 (CNCF 대부분 요구)
git config alias.cs "commit -s"    # 항상 -s (Signed-off-by)
```

## Step 4 — 첫 기여 고르기 (작게!)

```
경로 A: 문서 (가장 확실한 시작)
  □ 커리큘럼 학습 중 그 프로젝트 문서에서 헤맸던 부분을 떠올려라
  □ 오타·깨진 링크·불명확한 설명·빠진 예제를 하나 찾아라
  □ 그것이 첫 PR

경로 B: 이슈 재현 (트리아지)
  □ needs-reproduction 상태의 이슈를 하나 골라
  □ kind로 재현 시도 (커리큘럼 실습 그대로!)
  □ 재현 성공 → 절차·로그를 코멘트로 (재현 실패도 정보)
  → PR 없이도 가치 있는 기여 + 이름을 알림

경로 C: good first issue
  □ CLOTributor(clotributor.dev) 또는 저장소 라벨에서
  □ 이미 누가 하고 있는지 확인 (assignee·코멘트)
  □ "I'd like to work on this" 코멘트 → 응답 기다린 후 시작
```

## Step 5 — 첫 PR (예절 포함)

```
□ 브랜치 파고 작업 — 한 PR은 한 가지만
□ 테스트 추가/통과 확인 (로컬에서 make test)
□ 커밋: git commit -s (DCO), 메시지는 프로젝트 컨벤션
□ PR 설명: 무엇을·왜 (Fixes #이슈번호), 스크린샷/재현(해당 시)
□ PR 템플릿의 체크리스트 성실히
□ CI 실패하면 스스로 확인·수정 (리뷰어 기다리게 하지 말 것)

리뷰가 오면:
□ 지적에 감사 표시, 신속히 수정 (방어 논쟁 X — 배움의 기회)
□ 이해 안 되면 정중히 질문 (침묵 후 잘못 고치기보다 낫습니다)
□ 1~2주 응답 없으면 정중한 ping, 그래도 없으면 슬랙에서 요청

머지되면:
□ 축하 — 회원님은 이제 그 프로젝트의 contributor다 🎉
□ 다음 이슈로 (꾸준함이 ladder의 연료)
```

## Step 6 — 첫 이슈 리포트 (운영 경험이 생기면)

커리큘럼 pitfalls에서 배운 함정을 실무·실습에서 실제로 만나면:

```
□ 최소 재현 만들기 (kind + 최소 매니페스트 — 커리큘럼 기술 그대로)
□ 기존 이슈 검색 (중복이면 그 이슈에 재현을 보태라 — 그것도 기여)
□ 템플릿 따라 리포트: 버전·환경·기대vs실제·재현 절차·로그
□ 보안 문제면 절대 공개 이슈 X → SECURITY.md 채널 (cicd 21)
```

## 완주 확인

```
이 랩의 "완료" 조건 (실제 수행):
  □ 대상 프로젝트 1개 선정 + 정찰 시트 작성
  □ 슬랙 가입 + 회의록/최근 PR 읽기
  □ 로컬 빌드·테스트 성공
  □ 첫 기여 1건 제출 (문서 PR / 이슈 재현 코멘트 / good first issue PR)

이 네 칸이 채워지면 — 커리큘럼의 실기 시험 통과입니다.
자격증 시험장이 아니라 실제 생태계에서.
```

## 정리

- 대상은 하나로 좁혀 (관심×역량×거버넌스) — 신뢰는 한 곳에서 쌓입니다
- 잠복 관찰(1~2주)이 49의 "석 달 사고"를 예방
- 첫 기여는 작게: 문서 / 이슈 재현 / good first issue — 커리큘럼 기술(kind 재현)이 그대로 무기
- DCO(-s)·테스트·한 PR 한 가지·예절 (지적은 배움, 인내는 미덕)
- **★ 머지된 첫 PR = 이 커리큘럼의 실기 졸업장 — 그리고 시작일 뿐**
