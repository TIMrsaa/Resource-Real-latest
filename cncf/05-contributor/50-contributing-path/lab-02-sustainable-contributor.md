# Lab 02 — 지속 가능한 기여자: ladder·멘토링·커뮤니티

> 첫 PR(lab-01)은 시작입니다. 이 랩은 그 다음 — 꾸준한 기여자로 자리 잡고, ladder를 오르고, 커뮤니티의 구성원이 되는 6~12개월의 계획을 세웁니다. 커리큘럼의 마지막 문서이자, 회원님의 첫 로드맵입니다.

## 1. 나의 기여 로드맵 작성 (실제로 쓸 것)

```
[3개월 목표]
  □ 주당 투자 시간 정하기 (현실적으로: 2~4시간이면 충분)
  □ 대상 프로젝트에서 PR ___건 (제안: 월 1~2건, 작은 것)
  □ 이슈 트리아지/재현 ___건
  □ 회의(SIG/커뮤니티 콜) 월 1회 이상 참관
  □ 슬랙에서 다른 사용자 질문에 답 시도 (커리큘럼 지식 활용)

[6개월 목표]
  □ 한 영역(컴포넌트·서브시스템)의 단골 되기
     — 그 영역 이슈·PR에 꾸준히 (넓게 얕게 X)
  □ 남의 PR 리뷰 코멘트 시작 (완벽하지 않아도 — 테스트 확인, 재현 확인)
  □ (해당 시) org member 신청 — 기여 이력 + 스폰서
     (K8s: 스폰서 2인, 다른 프로젝트는 GOVERNANCE 확인)

[12개월 방향]
  □ reviewer 후보 될 만큼 그 영역 리뷰 이력 쌓기
  □ LFX Mentorship 지원 또는 (역량 되면) 멘토 측 참여
  □ KubeCon(또는 지역 밋업·KCD Korea) 참가 — 얼굴 익히기
```

## 2. LFX Mentorship 지원 전략

```
준비:
  □ mentorship.lfx.linuxfoundation.org 에서 기수 일정 확인
     (봄/여름/가을 기수, 프로젝트별 과제 공고)
  □ 관심 프로젝트의 과제 찾기

지원서에 쓸 것 (경쟁력):
  ★ 이미 한 기여 (lab-01의 첫 PR·이슈가 여기서 빛납니다
     — "하고 싶다"보다 "이미 하고 있다"가 강력)
  커리큘럼에서 쌓은 도메인 이해 (구체적으로:
    "Prometheus TSDB의 블록 구조를 알고 카디널리티 실습을 했다")
  과제와 내 역량의 연결

멘토십 기간:
  공개적으로 일하기 (진행을 이슈·PR로)
  막히면 빨리 묻기 (혼자 2주 끙끙 X — 멘토는 그러라고 있습니다)
  기수 후에도 남기 (멘토십은 진입로지 목적지가 아님)
```

## 3. 리뷰어로 가는 길 — 받는 쪽에서 주는 쪽으로

```
리뷰 시작이 어렵게 느껴지는 이유: "내가 뭐라고 남의 코드를..."
현실: 리뷰는 승인이 아니라 도움입니다. 초보 리뷰어도 가능한 것:

  □ PR을 로컬에서 돌려보고 "동작 확인했다" 코멘트
     (재현·검증 — 커리큘럼 실습 기술!)
  □ 테스트 없는 수정에 "이 케이스 테스트 추가하면 어떨까요?"
  □ 문서 변경의 오타·명확성 지적
  □ "이 부분이 이해 안 되는데 설명해 줄 수 있나요?"
     (좋은 질문은 좋은 리뷰 — 문서화 필요성의 신호)

→ approver의 부담을 덜어주는 모든 것이 리뷰 기여
→ 이 이력이 OWNERS 등재(reviewer)의 근거가 됩니다
```

## 4. 커뮤니티 활동 — 코드 밖의 성장

```
국내:

  □ KCD(Kubernetes Community Days) Korea
  □ K8s 문서 한국어 번역 (SIG-Docs ko — 진입 장벽 낮고 수요 높음)

글로벌:
  □ KubeCon + CloudNativeCon (Contributor Summit이 기여자 온보딩)
  □ TAG 회의 (49 — 문서·자문 기여)
  □ 프로젝트 커뮤니티 콜

발신도 기여:
  □ 트러블슈팅 경험 블로그 (커리큘럼 pitfalls + 실제 경험)
  □ 밋업 발표 (작은 것부터 — "첫 기여 후기"도 훌륭한 주제)
  → 채택을 돕고, 이름을 알리고, 생태계를 키웁니다
```

## 5. 번아웃 방지 계약 (자신과)

```
□ 주당 상한을 정합니다 (하한만큼 중요 — 지속 > 폭발)
□ 재미없어지면 영역을 바꿉니다 (의무가 되는 순간 끝이 보입니다)
□ 거절된 PR·무응답을 개인화하지 않습니다 (49 — 합의 비용·자원봉사)
□ 최소 단위를 정합니다 ("바쁜 주엔 이슈 하나 읽기"도 유지)
□ 성과를 기록합니다 (머지 PR 목록 — 정체감 들 때 되돌아볼 것)
```

```
Part 1 k8s: 쿠버네티스라는 땅

Part 3 cicd: 소프트웨어가 흐르는 길
Part 4 cncf: 생태계 전체
  01~10 지형 → 11~45 심층 → 46~48 조립·판단 → 49~50 구성원으로

이 커리큘럼이 준 것:
  지식(각 모듈) + 연결(상호참조) + 판단(트레이드오프)
  + 항해술(45) + 지도(49) + 길(50)

이 커리큘럼이 주지 못하는 것:
  걷기 — 그것은 회원님의 몫

★ 완주를 축하합니다. 이제 소비자에서 구성원으로.
  생태계는 회원님 같은 사람들이 만들어 왔고, 만들어 갈 것입니다.
```

## 정리

- 로드맵: 3개월(작은 기여 습관)→6개월(한 영역 단골·member)→12개월(reviewer 방향)
- LFX는 "이미 하고 있다"가 최강 지원서 — lab-01의 첫 기여가 재료
- 리뷰는 승인이 아니라 도움 — 동작 확인·테스트 제안부터 (받는 쪽→주는 쪽)
- 국내(밋업·번역)와 글로벌(KubeCon·TAG) 모두 길 — 발신도 기여
- 번아웃 방지: 상한 설정·재미 우선·개인화 금지·기록
- **★ 커리큘럼의 끝 = 기여 생활의 시작. 소비자에서 구성원으로.**
