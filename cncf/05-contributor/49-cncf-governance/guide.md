# 학습 가이드 — 코드 뒤의 정치학(좋은 의미로)

## 왜 거버넌스를 배우나

"기여는 코드만 잘 쓰면 되는 것 아닌가?"라고 생각하기 쉽습니다. 하지만:

```
기여가 겉도는 이유의 대부분은 거버넌스 무지:
  "PR을 냈는데 몇 달째 반응이 없어요"
    → 그 저장소의 OWNERS·리뷰 프로세스를 몰랐습니다
  "기능 제안이 거절됐어요"
    → 제안은 SIG 회의·KEP(제안 문서)로 가야 했습니다
  "어느 저장소에 이슈를 내야 할지 모르겠어요"
    → 프로젝트의 SIG 구조를 몰랐습니다
→ 거버넌스는 "누가·어디서·어떻게 결정하나"의 지도
  이 지도 없이 기여하면 길을 잃습니다
```

50(기여 실전)의 성공률은 49(지도)에 달렸습니다.

## CNCF의 큰 구조 — 01의 복습과 심화

01에서 배운 뼈대를 확장합니다:

```
CNCF (Linux Foundation 산하)
├── Governing Board (GB) — 돈·전략 (기업 회원)
├── TOC (Technical Oversight Committee) — 기술 방향 (선출)
│     ├── 프로젝트 승인·졸업 심사
│     └── TAG들 감독
├── TAG (Technical Advisory Groups) — 도메인별 기술 자문
│     (예: TAG Security, TAG Observability, TAG App Delivery...)
└── End User Community — 사용 기업의 피드백

핵심 설계: 돈(GB)과 기술(TOC)의 분리
  → 돈 낸 기업이 기술 방향을 사지 못하게 (벤더 중립)
  → 01에서 "왜 이 분리가 중요한가"를 스쳤습니다 — 여기서 실감
```

## 프로젝트의 일생 — 성숙도의 실체

45에서 성숙도로 채택을 판단했습니다. 이제 그 단계가 **어떻게 매겨지는지**를 봅니다:

```
진입: Sandbox 신청 → TOC 검토 (기준: 클라우드 네이티브 적합, 거버넌스 의지)
성장: Incubating 승격 — 실 사용자, 기여자 다양성, 거버넌스 정착 증명
졸업: Graduated — 엄격한 심사 (Due Diligence)
  기여자 다양성(한 회사 의존 X), 거버넌스 문서, 보안 감사,
  채택 사례, 커뮤니티 건강...
→ 45에서 "Graduated를 신뢰"한 근거가 이 심사 과정
```

## Kubernetes의 SIG 체계 — 가장 중요한 사례

K8s는 너무 커서 SIG(Special Interest Group)로 나뉩니다:

```
SIG-Node(kubelet·런타임), SIG-Network, SIG-Storage,
SIG-Scheduling, SIG-Auth, SIG-Docs, SIG-Release...
각 SIG: 자기 영역의 코드·리뷰·설계를 소유
WG(Working Group): SIG를 가로지르는 한시적 주제

의미: "Kubernetes에 기여"란 실제로 "어느 SIG에 기여"
  기능 제안 = KEP(Kubernetes Enhancement Proposal) → 해당 SIG 승인
  → 50에서 첫 기여 대상을 고를 때 이 지도가 필수
```

## 거버넌스 문서 읽기 — 기여 전 정찰

모든 건강한 프로젝트엔 거버넌스 문서가 있습니다:

```
GOVERNANCE.md — 의사결정 구조 (누가 무엇을 결정)
OWNERS / CODEOWNERS — 디렉터리별 리뷰어·승인자
CONTRIBUTING.md — 기여 절차 (DCO 서명, 테스트, PR 규칙)
MAINTAINERS.md — 메인테이너 명단과 되는 길(사다리)
CODE_OF_CONDUCT.md — 행동 규범
```

이 문서들을 읽는 것이 기여의 첫걸음입니다(lab-02에서 훈련). 그리고 이 문서들의 **존재와 품질 자체가** 45의 프로젝트 건강 판단 지표입니다 — 거버넌스 문서가 없거나 형식적인 프로젝트는 "한 회사 의존" 리스크가 높습니다.

## 이 모듈의 관점 — 기여자의 눈

지금까지 우리는 **사용자**의 눈으로 프로젝트를 봤습니다(설치·운영·판단). 이 트랙부터는 **기여자**의 눈입니다:

```
사용자의 질문: "이걸 어떻게 쓰나요?"
기여자의 질문: "이건 누가 어떻게 만들고 결정하나요?
              나는 어디에 어떻게 참여하나요?"
```

이 시선 전환이 커리큘럼의 최종 목표 — 생태계의 소비자에서 **구성원**으로.
