# 49 — CNCF 거버넌스: 생태계는 어떻게 운영되는가

> 01에서 CNCF의 뼈대(GB↔TOC 분리, 성숙도 3단계)를 스쳤습니다. 이제 기여자가 되기 위해 그 구조를 제대로 압니다. 오픈소스 프로젝트는 저절로 굴러가지 않습니다 — **누가 방향을 정하고(TOC), 누가 실무를 하고(SIG·TAG), 프로젝트는 어떻게 들어오고 자라며(Sandbox→Incubating→Graduated), 벤더 중립은 어떻게 지켜지는가(재단·거버넌스)**. 이 구조를 알아야 기여가 겉돌지 않습니다 — 어디에 제안을 내야 하는지, 왜 어떤 PR은 몇 달을 기다리는지, 프로젝트의 건강을 어떻게 읽는지(45의 지속성 판단)가 전부 거버넌스에서 나옵니다. 이 모듈은 CNCF의 운영 구조와, 개별 프로젝트(Kubernetes의 SIG 체계 등)의 거버넌스를 다뤄 50(기여 실전)의 지도를 그립니다.

## 학습 목표

1. CNCF의 구조(GB·TOC·TAG·End User Community)와 각 역할·견제를 압니다
2. 프로젝트 수명주기(Sandbox 신청→Incubating→Graduated 졸업 심사)를 압니다
3. Kubernetes의 SIG/WG 체계(누가 무엇을 결정하나)를 압니다
4. 프로젝트 거버넌스 문서(GOVERNANCE.md·OWNERS·메인테이너 사다리)를 읽는 법을 압니다
5. 거버넌스로 프로젝트 건강(지속성·벤더 중립·의사결정 투명성)을 판단합니다(45 심화)
