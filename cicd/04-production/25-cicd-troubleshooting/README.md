# 25 — CI/CD 트러블슈팅: 파이프라인이 멈춘 날의 진단학

> 파이프라인 장애는 서비스 장애와 다릅니다 — 고객 대신 **조직 전체의 배포 능력**이 멈춥니다(장애 수정 배포조차 파이프라인을 지나야 하는 재귀!). 이 모듈은 Part 3의 실무 총결산입니다: 배운 모든 층(캐시 19·20, 러너 08·23, OIDC 07, GitOps 14·15, 이미지 04·21)의 장애를 진단 카드 10장으로 체계화하고, 대표 시나리오를 직접 부수고 고치며, "파이프라인 온콜"의 조직 규율까지 다룹니다. eks 26(진단 카드)의 CI/CD판.

## 학습 목표

1. 파이프라인 장애의 첫 분류(항상 vs 간헐 / 내 코드 vs 파이프라인 vs 플랫폼)를 반사적으로 수행합니다
2. 진단 카드 10장 — 증상→가설 순서→확인 명령→처방 — 을 체득합니다
3. 3대 고전(캐시 오염, 러너 고갈, 동시성 데드락)을 재현하고 진단합니다
4. "배포는 됐는데 옛 버전" 류의 경계 장애(파이프라인은 성공, 결과는 실패)를 다룹니다
5. 파이프라인 장애의 조직 대응(머지 동결 선언, 온콜, 포스트모템→게이트화)을 압니다
