# 흔한 함정 5선

## 1. path filter를 의존성 있는 폴더에 사용

`paths: ['services/api/**']`는 api 폴더의 변경만 봅니다 — api가 import하는 `libs/shared`의 변경은 api를 안 돌립니다. 필터에 shared를 수동 추가해도 그 목록은 의존성 그래프의 **낡는 사본**입니다(새 import 하나가 목록 갱신을 요구하고, 아무도 갱신하지 않습니다). path filter는 의존성이 없는 독립 영역(docs/, 인프라 매니페스트)에만. 코드 프로젝트에는 그래프 기반 affected(Nx/Turbo)를.

## 2. 매트릭스 잡 이름을 required check로 등록

동적 매트릭스의 잡("test (@mono/web)")을 브랜치 보호의 required check로 걸면, 그 프로젝트가 affected가 아닌 PR에서 잡이 생성되지 않고 — GitHub은 스킵/미생성을 통과로 안 쳐서 "expected" 상태로 **영원히 대기**, 무고한 PR이 머지 불가가 됩니다. required check는 `if: always()`로 항상 도는 단일 `ci` 게이트 하나만(03의 패턴). 게이트 안에서 skipped를 통과로, failure만 차단으로 판정합니다.

## 3. 얕은 클론에서 affected 계산

GHA 기본 checkout은 `fetch-depth: 1` — base 커밋이 없어서 diff 계산이 안 되고, 도구는 (안전하게) **전부 affected**로 처리하거나 에러를 냅니다. "affected를 붙였는데 매번 전체가 돈다"의 1번 원인. `fetch-depth: 0`(또는 base를 포함할 만큼의 depth)을 명시하세요. 같은 이유로 base 브랜치 참조(`origin/main`)가 러너에 fetch되어 있는지도 확인.

## 4. 태스크 입력의 거짓 선언 — 캐시가 낡은 출력을 재생

태스크가 선언 안 된 입력(환경변수, 루트 설정 파일, 생성 코드)에 실제로 의존하면, 그 입력이 바뀌어도 해시가 같아 **낡은 캐시가 재생**됩니다 — "고쳤는데 CI는 옛날 결과를 준다"는 미스터리(25의 캐시 오염 시나리오). 환경변수는 `env`/`globalEnv`에, 전역 파일은 `globalDependencies`에 선언. Bazel이 샌드박스로 강제하는 것을 Nx/Turbo에서는 규율로 지켜야 합니다 — 캐시의 신뢰도는 입력 선언의 정직함에 비례합니다.

## 5. 원격 캐시를 신뢰 경계 없이 공유

원격 캐시는 "누군가 빌드한 출력을 모두가 재사용"입니다 — 뒤집으면 **캐시에 쓸 수 있는 사람은 모두의 빌드 산출물에 쓸 수 있습니다**. 포크 PR(03의 신뢰 경계!)이 캐시에 쓰기 가능하면, 악성 PR이 오염된 출력을 심고 main 빌드가 그것을 재생합니다 — 공급망 공격의 캐시판. 쓰기는 신뢰된 브랜치(main)의 CI만, PR은 읽기 전용으로. 21의 공급망 관점이 캐시에도 적용됩니다.

## 실무 사고 사례

> 40여 개 패키지의 프런트엔드 모노레포를 운영하던 조직 — CI가 커밋당 35분이 되자 path filter를 도입해 "바뀐 패키지만" 돌리게 했습니다. 석 달간 빨랐고, 석 달 뒤 사고가 왔습니다. 디자인 시스템 패키지의 버튼 컴포넌트 prop 기본값 변경이 머지됐는데 — 필터 목록에 디자인 시스템을 소비자들과 연결하는 항목이 빠져 있어(6주 전 새로 생긴 패키지 3개가 목록에 반영 안 됨) 소비자 테스트가 전혀 돌지 않았습니다. 결제 페이지의 버튼이 프로덕션에서 비활성 상태로 렌더링됐고, 매출 그래프가 먼저 알아챘습니다. 포스트모템의 결론이 정확했습니다: "우리는 의존성 그래프를 YAML에 수동으로 복사하고 있었고, 사본은 반드시 낡습니다." 조직은 Nx affected로 이전했습니다 — 그래프를 import에서 자동 추출하므로 새 패키지가 생기면 그래프에 저절로 들어갑니다. 이전 후 첫 달에 affected가 잡아낸 "path filter라면 놓쳤을 회귀"가 4건. 교훈: **모노레포 CI에서 수동 목록은 전부 부채입니다** — 그래프는 코드에서 추출되어야 하고, 그래프가 못 보는 것(계약·환경)은 목록이 아니라 다른 종류의 테스트(05)가 맡아야 합니다.
