## 정답

**A1.** 이벤트 → 워크플로 → 잡 → 스텝. 스텝↔스텝(같은 잡): 파일시스템·워크스페이스 공유, **셸 변수는 비공유**(각 `run:`이 새 셸). 잡↔잡: **아무것도 공유 안 됨**(다른 러너 VM) — outputs/artifacts로만 전달. 워크플로끼리는 실행 컨텍스트 비공유.

**A2.** 각 스텝은 독립된 셸 프로세스라서 `export`는 그 스텝에서만 삽니다. 방법: ① `echo "VAR=x" >> "$GITHUB_ENV"` (이후 스텝의 환경변수) ② `echo "key=x" >> "$GITHUB_OUTPUT"` + `steps.<id>.outputs.key` (명시적 출력).

**A3.** `needs`(순서·의존 + 앞 잡 outputs 접근), `outputs`(작은 문자열 값), `artifacts`(파일/디렉터리 — upload/download). 기준: 작은 값이면 outputs, 파일이면 artifacts, 순서만 필요하면 needs. 잡 분할은 병렬성을 얻지만 아티팩트 전송 비용을 냅니다.

**A4.** ① 체크아웃 기본이 PR 코드 vs base 브랜치 코드 ② 포크 PR에서 시크릿 없음 vs **있음** ③ GITHUB_TOKEN이 읽기 전용 vs 쓰기 가능. 절대 금지: `pull_request_target`에서 `github.event.pull_request.head.sha`를 체크아웃해 **PR의 코드를 빌드/실행**하는 것 — 시크릿이 있는 컨텍스트에서 남의 코드가 돕니다.

**A5.** `${{ }}` 표현식은 러너의 셸 파싱 **이전에** 문자열로 치환되므로, PR 제목에 `"; malicious; #` 같은 셸 메타문자가 있으면 그대로 명령이 됩니다. 방어: `env: TITLE: ${{ ... }}`로 값 전달 후 `run: echo "$TITLE"` — 환경변수는 값이지 코드가 아닙니다.

**A6.** ① 매트릭스에 버전을 **추가**하면 그 잡은 필수가 아닙니다(검사 누락) ② 버전을 **제거**하면 등록된 필수 검사가 영원히 pending이 되어 모든 PR이 막힙니다. 해법: `needs: [lint, test]` + `if: always()`로 결과를 집계하는 **수렴 잡 하나**(`ci`)만 필수 검사로 등록.

**A7.** 이점: 완전한 재현성 — "내 노트북에선 되는데"가 사라지고, 이전 실행의 오염(설치된 툴, 남은 파일)이 없습니다. 대가: 매번 의존성을 새로 받아야 하므로 **캐시를 명시적으로 관리**해야 하고, 빌드 캐시가 자동으로 누적되지 않습니다.

**A8.** 태그는 **움직이는 포인터**라 액션 저장소가 탈취되거나 태그가 재지정되면, 다음 실행부터 악성 코드가 시크릿이 있는 우리 러너에서 실행됩니다. 대안: 커밋 **SHA로 고정**(`@8ade135a...`) + Dependabot으로 갱신 PR 수신, 그리고 조직 차원의 허용 액션 목록.
