# 학습 가이드 — YAML을 외우지 말고 실행 모델을 이해하세요

## 이 모듈을 읽는 법

GitHub Actions 튜토리얼은 넘칩니다. 대부분은 YAML 조각을 보여주고 "이렇게 하면 됩니다"로 끝납니다. 그런 자료로 배운 사람은 이런 순간에 무너집니다:

- 앞 스텝에서 `export VAR=x` 했는데 다음 스텝에서 `$VAR`가 비어 있습니다
- 잡을 나눴더니 앞 잡이 만든 파일이 사라졌습니다
- PR에서 시크릿이 안 읽힙니다 (포크에서 온 PR이라)
- 워크플로가 자기 자신을 무한 트리거합니다

이 넷은 모두 **실행 모델을 모르면 미스터리이고, 알면 자명한 것**들입니다. 그래서 이 모듈은 문법이 아니라 구조를 먼저 세웁니다:

```
이벤트  — GitHub에서 일어난 일 (push, PR, schedule, 수동…)
 └ 워크플로 — .github/workflows/*.yml 하나
     └ 잡    — 러너 머신 하나. 잡끼리는 병렬이 기본, 파일시스템 격리
         └ 스텝 — 같은 러너, 같은 파일시스템. 단 셸 프로세스는 매번 새로
```

**격리 경계가 어디에 있는지**가 위 네 미스터리의 답입니다.

## 보안을 처음부터

`pull_request_target`과 스크립트 인젝션은 "고급 주제"로 미뤄지곤 하는데, 그 사이에 사고가 납니다 — 포크 PR이 저장소의 시크릿을 훔치는 고전적 공격입니다. 이 모듈은 기초에서 그 경계를 명시합니다(theory §3, §5). 21(공급망 보안)에서 깊이 들어가지만, **위험한 트리거를 배우기 전에 위험을 아는 것**이 순서입니다.
