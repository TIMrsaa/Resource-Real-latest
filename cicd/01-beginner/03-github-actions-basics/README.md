# 03 — GitHub Actions 기초: 이벤트가 워크플로를 부릅니다

> 02에서 브랜치 보호에 `ci`라는 필수 검사를 선언했지만 그것을 제공하는 자가 없어 머지가 막혔습니다. 이 모듈이 그 `ci`를 만듭니다. 그리고 그 과정에서 Actions의 실행 모델 — **이벤트 → 워크플로 → 잡(러너 하나) → 스텝(같은 파일시스템)** — 을 실측으로 확인합니다. YAML 문법을 외우는 모듈이 아니라, "왜 스텝 사이에 변수가 안 넘어가는가" 같은 질문에 구조로 답할 수 있게 되는 모듈입니다.

## 학습 목표

1. 실행 모델 4층(이벤트/워크플로/잡/스텝)과 각 층의 **격리 경계**를 압니다
2. 트리거의 함정을 이해합니다 — `push` vs `pull_request` vs `pull_request_target`(보안!)
3. 잡 간 통신 수단 3종(needs·outputs·artifacts)을 구분해 씁니다
4. 컨텍스트·표현식·시크릿의 평가 시점을 압니다 — 스크립트 인젝션 방어
5. 02의 브랜치 보호를 만족하는 `ci` 워크플로를 완성하고, 캐시로 시간을 줄입니다

## 선행: 01(파이프라인 3원칙), 02(브랜치 보호 — 이 모듈이 그 게이트를 채웁니다) · 도구: gh CLI, GitHub 계정
